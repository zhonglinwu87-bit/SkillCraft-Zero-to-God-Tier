# L3-01：一键发布公众号 —— 全自动排版+配图+发布流水线

> 🎯 **学什么**：学会用 AI 全自动把 Markdown（Markdown：纯文本排版格式）文章排版、配图、一键发布到微信公众号——打通「格式转换→图片处理→样式选择→CDP（CDP：Chrome 开发者工具协议）发布」完整五步流水线（pipeline：多步骤流水线）。核心洞察：微信公众平台是格式地狱（禁 CSS（CSS：网页样式语言）/JS（JS：网页脚本语言），只接受内联样式），但这个 Skill 把它变成了你只需写 Markdown 的无感体验。
> 💡 **难易度**：⭐⭐ | ⏱️ **预计时间**：45 分钟

***

## 1. 课程概览

> 💡 **白话小课堂**：这个 Skill 就像一个**全自动排版机器人秘书**——你把 Markdown（Markdown：纯文本排版格式）文章给它，它自动把 Markdown 转成微信兼容的 HTML（HTML：网页标记语言）（所有样式内联化）、把外链图片上传到微信服务器、选一套预设主题样式、然后像一个真人一样在浏览器里打开微信后台、粘贴内容、点击发布。你从前花 3 小时排版调格式，现在花 0 分钟——你的脑子留给最重要的：写什么内容。

> **本课的独特定位**——Level 3 的第一个流水线 Skill：

| 特征 | L2-14（Markdown转PPT） | L3-01（本课） |
|------|----------------------|-------------|
| 步骤数 | 4 步 | **5 步** |
| 核心挑战 | 模板匹配 | **格式约束地狱** |
| 平台特性 | 通用导出 | **微信专属格式战争** |
| 验证要求 | 导出即完 | **必须真机验证** |

> 🔑 **核心秘诀**：微信公众号的格式约束不是"不方便"——是"反人类"。外部 CSS 被禁、JavaScript 被禁、外链图片不显示、不同手机渲染结果不同。这个 Skill 不是"帮你排版"，而是"帮你打赢微信的格式战争"——你只管写 Markdown，它管把所有格式约束逐一击破。

> ⚠️ **避坑指南**：电脑上预览好看≠手机上好看。微信在不同手机上的 CSS 渲染差异巨大——字体大小、行间距、图片对齐、列表缩进，在 iPhone 和安卓上可能完全不同。做完一定要用手机预览！

## 2. 微信公众平台的格式地狱

### 2.1 四大格式约束

微信公众平台的文章编辑器不是标准的 HTML（HTML：网页标记语言）环境——它是一个被高度阉割的富文本编辑器：

```
约束 1: 不支持外部 CSS
  → 所有样式必须写成内联（inline style="..."）
  → <link> 标签被过滤，<style> 标签在正文中失效
  → 你从 Word/Notion 复制的内容，格式全丢

约束 2: 不支持 JavaScript
  → 任何 <script> 标签被过滤
  → 交互效果全部失效（轮播图、折叠面板、动态图表）
  → 只接受纯静态的 HTML + 内联 CSS

约束 3: 图片必须上传到微信服务器
  → 外链图片（<img src="https://...">）不显示
  → 必须先通过微信后台的文件上传接口把图片传到微信服务器
  → 微信会重新压缩所有图片（有时画质损失严重）

约束 4: 样式在不同手机上渲染不同
  → 微信内置浏览器在不同手机上的 CSS 渲染引擎存在差异
  → 字体大小、行间距、图片对齐、列表缩进在 iPhone vs 安卓可能完全不同
  → 电脑端编辑器预览 ≠ 手机端真机效果
```

### 2.2 为什么微信要这样做？

```
安全考虑：
  → 禁用 JS（JS：网页脚本语言）防止 XSS 攻击和恶意脚本
  → 过滤外部 CSS 防止样式注入
  → 图片上传到微信服务器防止外链追踪和内容替换

体验考虑：
  → 统一阅读体验——所有文章在微信内置浏览器里看起来差不多
  → 图片缓存加速——微信服务器上的图片加载更快

代价：
  → 内容创作者的格式控制权被严重剥夺
  → 排版工作量剧增——每次发布都要手动调格式
```

## 3. 五步流水线详解

### 3.1 完整链路

```
Markdown 文章
  ↓ Step 1: 识别内容类型
  判断是纯文字/图文混排/视频文章/头条文章
  ↓ Step 2: 格式转换（Markdown → 微信兼容 HTML）
  所有样式内联化，外部资源本地化
  ↓ Step 3: 图片处理
  外链图片 → 下载 → 上传微信服务器 → 替换 URL（URL：网页地址）
  ↓ Step 4: 样式选择
  从预设主题库中匹配最佳样式方案
  ↓ Step 5: CDP 发布
  Chrome DevTools Protocol 操控浏览器完成发布
```

### 3.2 Step 1：识别内容类型

在开始格式转换之前，AI 先判断文章的类型——不同类型的文章对应不同的格式策略：

```
类型判断逻辑：

纯文字文章（无图片/无视频）：
  → 关注点：段落间距、标题层级、列表格式
  → 格式策略：最大化文字阅读体验

图文混排文章（有图片，无视频）：
  → 关注点：图片尺寸适配、图文间距、图片说明样式
  → 格式策略：图片与文字的视觉节奏

视频文章（含视频）：
  → 关注点：视频卡片样式、视频与文字的过渡
  → 格式策略：视频卡片作为视觉焦点

头条文章（长文，含封面）：
  → 关注点：封面图、摘要、正文内的小标题层级
  → 格式策略：封面吸引点击 + 正文结构导航
```

### 3.3 Step 2：格式转换（Markdown → 微信兼容 HTML）

这是整个流水线最关键的一步——把 Markdown 的所有格式元素逐一翻译成微信能接受的内联 HTML：

```
转换规则：

标题：
  Markdown # 标题 → <h1 style="font-size:22px; font-weight:bold; margin:20px 0 10px; color:#333;">标题</h1>
  Markdown ## 标题 → <h2 style="font-size:20px; ...">标题</h1>
  ...（h1-h6 各配默认样式）

段落：
  Markdown 段落 → <p style="font-size:15px; line-height:1.75; color:#3f3f3f; margin:0 0 15px;">段落文字</p>

加粗/斜体：
  **加粗** → <strong style="font-weight:bold;">加粗</strong>
  *斜体* → <em style="font-style:italic;">斜体</em>

链接：
  [文字](url) → <a href="url" style="color:#576b95; text-decoration:none;">文字</a>

图片：
  ![alt](url) → 先保留占位符 <!-- IMAGE: url -->（Step 3 中替换）

列表：
  - 无序列表 → <ul style="padding-left:20px; margin:10px 0;">
                <li style="margin-bottom:5px;">条目</li></ul>
  1. 有序列表 → <ol style="padding-left:20px; margin:10px 0;">...</ol>

代码块：
  ```code``` → <pre style="background:#f5f5f5; padding:15px; border-radius:4px; 
                    font-family:monospace; font-size:13px; overflow-x:auto;">
                  <code>code内容</code></pre>

引用：
  > 引用 → <blockquote style="border-left:4px solid #ddd; padding:10px 15px; 
                         margin:15px 0; color:#666; background:#f9f9f9;">引用文字</blockquote>
```

> 🔑 **设计要点**：为什么 Step 2 和 Step 3 必须分开？图片上传是异步操作（需等待微信服务器响应），混在格式转换中会导致一张图片上传失败卡住整篇文章的发布流程。分开做：格式转换先确定图片列表，图片处理独立逐张上传，哪张失败重试哪张，不阻塞整体流程。

### 3.4 Step 3：图片处理

图片处理是独立步骤——与格式转换解耦，实现失败隔离：

```
图片处理流程：

1. 从转换后的 HTML 中提取所有 <!-- IMAGE: url --> 占位符
2. 对每个图片 URL：
   a. 下载图片到本地临时目录
   b. 检查图片尺寸（微信推荐宽度：900px，最大 10MB）
   c. 如果需要，resize 到推荐尺寸（保留宽高比）
   d. 通过 CDP 上传到微信服务器（模拟在编辑器中点"图片"→"上传"）
   e. 获取微信返回的图片 URL（mmbiz.qpic.cn 域名）
   f. 替换 HTML 中的占位符为 <img src="微信URL" style="max-width:100%;">
3. 所有图片上传完成后，继续下一步

失败处理：
  → 单张图片上传失败 → 重试 3 次（间隔 2 秒）
  → 3 次后仍失败 → 保留外链 URL，标记为"手动处理"
  → 不阻塞其他图片和整体流程
```

### 3.5 Step 4：样式选择

预设主题库——用户不需要手动调样式，选择一个主题即自动应用全套格式：

```
主题体系（示例）：

「简约阅读」主题：
  → 字体：系统默认（苹方/微软雅黑）
  → 字号：正文 15px，标题 18-22px
  → 行高：1.75
  → 配色：正文 #3f3f3f，标题 #1a1a1a，链接 #576b95
  → 适合：个人博客、技术文章、长文阅读

「品牌商务」主题：
  → 字体：思源黑体
  → 字号：正文 14px，标题 20-24px
  → 行高：1.8
  → 配色：正文 #333，标题 #1a1a1a，链接 品牌色
  → 适合：企业宣传、产品功能介绍

「文艺清新」主题：
  → 字体：思源宋体（标题）/ 系统默认（正文）
  → 字号：正文 16px，标题 20px
  → 行高：2.0
  → 配色：正文 #595959，标题 #bfa07a，链接 #8b7355
  → 适合：生活方式、旅行日记、美食推荐

「活力促销」主题：
  → 字体：系统默认
  → 字号：正文 15px，标题 22-26px
  → 行高：1.6
  → 配色：正文 #333，标题 #e74c3c，重点色 #f39c12
  → 适合：电商促销、活动推广、限时优惠
```

### 3.6 Step 5：CDP 发布

最后一步——CDP（Chrome DevTools Protocol）模拟真人在浏览器中操作微信公众平台后台：

```
CDP 发布流程：

1. 环境诊断：
   → 检查 Chrome 是否运行在调试模式（--remote-debugging-port=9222）
   → 检查微信公众平台是否已登录（cookie 是否有效）

2. 打开微信公众平台：
   → 导航到 mp.weixin.qq.com
   → 点击「新建文章」

3. 填充内容：
   → 粘贴 Step 2 转换后的 HTML（含 Step 3 替换好的图片 URL）
   → 填写标题
   → 填写摘要（如果是头条文章）

4. 发布/预览：
   → 先点击「预览」→ 发送到手机微信预览
   → 用户手机确认后 → 点击「群发」
   → 获取已发布文章的链接

关键反检测措施：
  → 随机延迟：每次操作间隔 500-2000ms（模拟人类打字和阅读节奏）
  → 鼠标轨迹：在元素间移动鼠标而非瞬间跳转
  → 不要过快发布——从打开到发布至少 30 秒（真人操作时间）
```

> 🔑 **设计要点**：CDP 在这里的作用和 L2-11（X/Twitter 发布）相同——通过操控真实浏览器发布内容。微信公众平台没有公开的发布 API（API：程序接口），CDP（CDP：Chrome 开发者工具协议）是唯一可行的自动化方式。但 CDP 的核心劣势是脆弱——微信后台改了 UI（UI：用户界面），脚本就需要更新。

## 4. 与 L2-11/L2-12 跨平台发布模式的对比

L3-01 的公众号发布与 L2-11（X/Twitter 发布）和 L2-12（微博发布）共享同一个四步骨架，但有一个关键差异——微信多了一个「格式转换」步骤：

| 步骤 | L2-11（X/Twitter） | L2-12（微博） | L3-01（公众号/本课） |
|------|-------------------|-------------|-------------------|
| 认证 | Chrome cookie | 扫码+会话保存 | Chrome cookie |
| 内容适配 | Thread 拆分、媒体压缩 | 长文、头条文章 | **Markdown→微信 HTML（内联 CSS）** |
| 图片处理 | Resize+转 WebP | 18 个文件上限 | **外链→上传微信服务器** |
| 执行发布 | CDP 浏览器操作 | CDP 浏览器操作 | CDP 浏览器操作 |
| 结果确认 | 截图+URL | 截图+URL | **手机预览→确认→发布** |

**为什么公众号比 X/微博多一步？** 因为微信的格式约束最极端——X 和微博的编辑器都接受标准 HTML，只有微信强制要求内联样式 + 服务器图片。这一步是微信独有的"格式转换层"，其他平台不需要。

## 5. 结构拆解：格式约束适配型 Skill 模板

```markdown
## 格式约束适配型 Skill 模板

### 核心特征
→ 目标平台有极端的格式约束（禁 CSS/JS/外链资源）
→ 核心挑战 = 将标准格式（Markdown）适配到平台专属格式
→ 关键设计 = 格式转换管线 + 资源上传隔离 + 真机验证

### 通用结构

## Platform Constraints（平台约束清单）
- 格式限制：[列出平台的格式禁用项]
- 资源限制：[图片/视频/文件的处理规则]
- 渲染差异：[不同设备的显示差异]

## Conversion Pipeline（转换管线）
Step 1: 内容类型识别
Step 2: 格式转换（源格式 → 平台兼容格式）
Step 3: 资源处理（外链资源 → 平台本地资源）
Step 4: 样式匹配（预设主题库）
Step 5: 执行发布（CDP 浏览器自动化）

## Verification（验证机制）
- 真机预览（必须！不同设备渲染不同）
- 格式完整性检查（图片是否显示、链接是否可点）
- 发布后立即抽查
```

**什么时候用格式约束适配型？** → 当目标平台对内容格式有特殊要求时：微信公众平台（禁 CSS/JS）、邮件客户端（各家的 HTML 支持不同）、某些CMS（CMS：内容管理系统）系统（只接受特定 HTML 子集）。核心是"翻译"——把用户熟悉的格式翻译成平台吃得消的格式。

## 6. 电商案例：女装品牌每周3篇公众号推文的自动化流水线

> 🛒 **实战案例**：淘宝「素白集」原创女装品牌（定位 25-35 岁通勤穿搭，客单价 ¥300-800），每周固定推送 3 篇公众号内容——周二新品上新（9 款单品图文）、周四搭配指南（穿搭教程长文）、周六品牌故事（设计师手记）。运营团队 2 人，每周花在公众号排版上的时间高达 11 小时：排版一篇新品推文 3.5 小时（9 款产品的图片逐张上传微信素材库、调字号/行距/对齐/留白）、穿搭长文 2.5 小时、品牌故事 2 小时。更麻烦的是——不同人排版标准不统一，新品推文和品牌故事看起来像两个不同的号，品牌视觉一致性无从保证。
>
> **用 post-to-wechat Skill 改造流程**：
> - Step 1 内容类型识别：新品推文=图文混排（9 张产品图+价格+面料说明）、穿搭指南=长文+步骤图、品牌故事=纯文字+氛围图
> - Step 2 格式转换：运营在 Notion 用 Markdown 写好内容 → Skill 一键转为微信兼容 HTML（所有内联 CSS、段落 15px/行高 1.75、标题 20px/品牌色 #8B7355）
> - Step 3 图片处理：Markdown 中引用的产品图外链 → Skill 自动下载 → 逐张上传微信服务器 → 替换为 mmbiz.qpic.cn 域名 URL，失败重试 3 次
> - Step 4 样式匹配：统一使用「品牌商务」主题——字体思源黑体、配色品牌色 #8B7355、标题 20px、正文 14px
> - Step 5 CDP 发布：自动打开微信后台 → 粘贴 HTML → 填写标题和摘要 → 发送手机预览 → 运营手机确认 → 群发
>
> **效果**：
> - 每周排版时间：11 小时 → 1.5 小时（Markdown 写作 1 小时 + 手机预览确认 30 分钟），节省 9.5 小时/周
> - 格式一致性：新品/穿搭/品牌三篇文章视觉统一度从"判若两号"提升到"一眼看出是同一个品牌"
> - 节省的 9.5 小时/周重新配置到：拍摄产品短视频（4h）、回复客户评论和私域运营（3.5h）、竞品分析（2h）
> - 公众号推文打开率：8.2% → 11.5%（格式统一+配图质量提升后，老读者更愿意点开）

> 🔑 **启示**：自动化不是目的，释放人的时间去做机器做不了的事才是目的。格式战争是纯技术活——机器打这个仗远比人打得好。人的时间应该花在「写什么」而不是「怎么排版」上。每周省下的 9.5 小时，拿来拍 3 条短视频、回复 200 条客户消息、分析竞品数据——这些才是GMV（GMV：商品交易总额） 的动作。

**Q4**：以下是一篇 Markdown 文章的发布流水线，正确的顺序是：
- A) 格式转换 → 图片处理 → 识别内容类型 → 样式选择 → CDP 发布
- B) 识别内容类型 → 格式转换 → 图片处理 → 样式选择 → CDP 发布
- C) 识别内容类型 → 样式选择 → 格式转换 → 图片处理 → CDP 发布
- D) 图片处理 → 识别内容类型 → 格式转换 → 样式选择 → CDP 发布

**Q5**：一个学员在电脑浏览器上预览公众号文章觉得排版完美，直接发布了，结果手机上标题错位、图片太大撑破屏幕。请诊断：他违反了哪个核心原则？正确的做法应该包含什么步骤？

**Q6**：如果你的公众号文章引用了外部网站的图片链接，发布后读者在手机上看不到这些图片，原因是：
- A) 微信会自动压缩所有图片
- B) 图片必须上传到微信服务器，外链图片不显示
- C) CDP 没有正确粘贴图片
- D) Markdown 不支持图片语法

**Q7**：小林用本 Skill 后，每周排版时间从 5 小时降到约 1 小时。如果他把省下的 4 小时/周用来拍短视频和写商品详情页，这体现了什么思维？请用课程中的概念来回答。

## 8. 答案

<details>
<summary>点击查看答案</summary>

**Q1**：**A、B、C** —— 微信不支持外部 CSS、不支持 JS、图片必须上传到微信服务器。D 错误，微信文章没有 5000 字限制。

**Q2**：**B** —— CDP 的核心优势是模拟真人在真实浏览器中的操作，微信无法区分真人和自动化。A 错误（CDP 不一定比爬虫快），C 错误（仍需登录），D 错误（运行在电脑上控制浏览器）。

**Q3**：参考答案——因为图片上传是异步的（需等待微信服务器响应）。混在一起会导致两个问题：(1) 一张图片上传失败会卡住整篇文章的发布流程；(2) 无法并行优化——格式出问题和图片出问题纠缠在一起，定位耗时长。分开做则：格式先确定图片列表，再逐张上传，哪张失败重试哪张，不阻塞整体流程。

**Q4**：**B** —— 正确顺序：识别内容类型 → 格式转换（Markdown→微信兼容 HTML）→ 图片处理（外链→上传微信服务器）→ 样式选择（预设主题）→ CDP 发布。

**Q5**：参考答案——他违反了"必须真机验证"原则。微信在不同手机上的 CSS 渲染效果不同，电脑浏览器预览不等于手机效果。正确做法：电脑编辑 → 发送手机预览 → 在手机上逐屏检查排版 → 确认无误后再发布。口诀：电脑写完→手机看完→确认发布。

**Q6**：**B** —— 微信不支持外链图片直接显示，所有图片必须先上传到微信服务器才能被读者看到。这是微信安全策略的一部分。

**Q7**：参考答案——这体现了"机会成本"思维和"时间投资回报"思维。不是单纯"省时间"，而是把省下的时间重新配置到更高杠杆的活动上（拍短视频获新客、优化详情页提升转化），让同样的工作时间产出更高的商业回报。核心是：自动化不是目的，释放人的时间去做机器做不了的事才是目的。

**评分**：（5/7 通过）
