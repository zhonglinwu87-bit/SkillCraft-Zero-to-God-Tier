# L5-11：企业内部沟通模板 —— 周报、公告、通知一键生成

> 🎯 **学什么**：让 AI 按照你们公司内部的"说话方式"来写周报、发公告、回 FAQ、写复盘报告。不是写标准的八股文，而是写"一看就知道是我们公司的人写的"那种内部文档。核心洞察：(1) 格式就是内容的一部分——一个用 3P 格式写了三年的团队，突然收到散文式周报，读者的第一反应不是文采好而是"出事了"；(2) 企业沟通的读者是高认知负荷人群——他们用 15 秒扫描模式读你的文档，倒金字塔结构不是在"创新"，是在"生存"；(3) 好模板的第一原则不是"写得好看"而是"让填写的人少动脑子"——用填空题代替作文题。
> 💡 **难易度**：⭐⭐⭐ | ⏱️ **预计时间**：30 分钟

***

## 1. 课程概览

> 💡 **白话小课堂**：每个公司都有自己独特的"内部行话"。有的公司周报用"3P 格式"（进展+计划+问题），有的用"OKR 格式"，有的老板只看数字、有的老板只看故事。internal-comms 不发明新格式——它遵循公司已有的格式，像一个"新入职但学得特别快"的同事，看一眼你的历史周报就学会了你的格式习惯。

## 2. 六种内部沟通类型

### 2.1 类型全景

internal-comms 覆盖六种最常见的内部沟通场景，每种有独立的格式规范和语气要求：

```
六种企业内部沟通类型：

类型 1：3P 更新（Progress / Plans / Problems）
  用途：周报、团队日常更新
  格式：三段式——本周完成什么 / 下周计划什么 / 遇到什么问题
  语气：直接、无修饰、用数字说话
  读者：直接上级 + 团队成员
  关键：Problems 段是不能省的——只报喜不报忧的周报失去 80% 的沟通价值

类型 2：公司新闻简报（Company Newsletter）
  用途：全公司范围内的重大更新、季度成果
  格式：倒金字塔——最重要信息在开头，背景在末尾
  语气：积极但不浮夸、事实为主
  读者：全公司（跨部门、跨层级）
  关键：简报 ≠ 微信推文——不需要"震惊！"式的标题

类型 3：FAQ 回答
  用途：回答公司内部常见问题（政策、流程、福利）
  格式：Q&A 对——一问一答，直接给出答案
  语气：简洁、准确、可被引用
  读者：可能包括新员工、跨部门同事
  关键：避免过度使用内部缩写——FAQ 读者的知识背景差异最大

类型 4：状态报告（Status Report）
  用途：项目阶段性汇报、里程碑检查
  格式：项目名 + 当前阶段 + 完成度% + 风险项 + 下个里程碑
  语气：客观、数据驱动、风险不隐瞒
  读者：项目干系人、管理者
  关键：风险项的写法——不止说"有风险"，要给出风险概率和影响

类型 5：领导层汇报（Leadership Update）
  用途：向高管/决策层汇报关键信息
  格式：一页纸以内——概要 + 核心数据 + 决策请求
  语气：极度精炼——删掉所有形容词
  读者：高管（阅读时间 < 60 秒）
  关键：高管需要的是"决策信息"，不是"操作细节"

类型 6：事件报告（Incident Report）
  用途：事故复盘——发生了什么、为什么、怎么防止再次发生
  格式：时间线 + 根因分析 + 影响范围 + 改进措施
  语气：客观、无责备、聚焦改进
  读者：技术团队 + 管理层
  关键：语气是无责备的——如果追责，团队下次会隐藏问题
```

### 2.2 类型选择决策树

```
当你收到一个内部沟通需求时，按以下顺序判断类型：

问 1：这个沟通是否涉及事故或线上故障？
  → 是 → 类型 6：事件报告
  → 否 → 继续

问 2：这个沟通的读者是 C-level 高管还是全公司？
  → C-level → 类型 5：领导层汇报
  → 全公司 → 继续

问 3：这个沟通是定期重复的（每周/每月）还是一次性的？
  → 定期 → 类型 1：3P 更新（或类型 4：状态报告，取决于粒度）
  → 一次性 → 继续

问 4：这个沟通的核心目的是"告知"还是"答疑"？
  → 告知 → 类型 2：公司新闻简报
  → 答疑 → 类型 3：FAQ 回答
```

## 3. 3P 格式深度拆解

### 3.1 三段式结构

3P 是内部沟通中最广泛使用的周报格式——不是因为最好，而是因为它用"填空题"替代了"作文题"：

```
3P 格式的三段结构：

📊 Progress（本周完成）
  写法：只写"完成的事"，不写"在做的事"
  错误示例：「在优化搜索功能」（这是在做的事）
  正确示例：「完成搜索功能优化，首页搜索响应时间从 1.2s → 0.3s」（完成+数字）
  长度：3-7 条
  关键规则：每条以动词开头——「完成」「上线」「修复」「发布」

📋 Plans（下周计划）
  写法：可验证的承诺，不是模糊的方向
  错误示例：「继续优化搜索功能」（不可验证）
  正确示例：「补齐搜索功能的 3 个边缘 case：空结果引导、拼音纠错、长尾词推荐」
  长度：3-5 条
  关键规则：下周结束时，别人能判断你"完成了"还是"没完成"

🚧 Problems（阻塞/风险）
  写法：问题 + 影响 + 你在尝试的方案 + 需要什么帮助
  错误示例：「搜索功能有 bug」（没有影响、没有方案、没有求助）
  正确示例：「搜索功能在 Safari 14 以下版本返回空结果（影响约 3% 用户），已排查到是 polyfill 兼容性问题，需要前端架构组协助——是否可以在周三前帮忙 review？」
  长度：0-3 条
  关键规则：这一节不能省——空的 Problems = 要么你不在认真工作，要么你在隐藏问题
```

### 3.2 Problems 段的沟通心理学

```
为什么空 Problems 段比有一个坏消息更危险：

场景 A：Problems = 空
  → 上级的解读：「这个人这周没遇到任何困难」
  → 两种可能：(1) 工作太简单，没挑战；(2) 有问题但不敢说
  → 无论哪种，都不是好信号

场景 B：Problems = 1 条具体的困难 + 尝试的解决方案 + 明确的帮助请求
  → 上级的解读：「这个人不仅能发现问题，还在主动推动解决，且知道需要什么资源」
  → 这是"靠谱"的信号

在企业沟通中：
  不暴露问题 ≠ 没有问题
  不暴露问题 = 问题正在暗中累积，直到爆发变成类型 6（事件报告）
```

## 4. 倒金字塔结构：企业沟通的生存法则

### 4.1 为什么不是正金字塔

```
正金字塔（学术写作/叙事写作）：
  引言 → 背景 → 分析 → 数据 → 讨论 → 结论
  → 读者需要读完全文才能理解核心信息
  → 适合：学术论文、长篇报告、文学作品

倒金字塔（企业写作/新闻写作）：
  核心结论 → 关键影响 → 支持数据 → 背景细节
  → 读者在任何一行停下来，都已经获得了最重要的信息
  → 适合：周报、简报、邮件、高管汇报

为什么企业沟通必须用倒金字塔？

  原因 1：读者是高认知负荷人群
    → 你的上司一天收到 80 封邮件 + 20 篇周报
    → 分配给你这篇文档的注意力 = 15 秒
    → 15 秒只能读前 3 行
    → 如果核心信息在第 4 段 → 你的文档对上司来说 = "没读到"

  原因 2：15 秒扫描模式 vs 5 分钟通读
    → 用了 3P 格式三年的团队，读者建立了"扫描模式"
    → 眼睛自动定位到 Progress→扫完成数→跳到 Problems→看在不在自己的关注范围
    → 15 秒完成
    → 突然换成散文式周报 → 扫描模式失效 → 需要通读找关键信息
    → 从 15 秒变成 5 分钟 → 认知摩擦爆炸
```

### 4.2 倒金字塔的每层写法

```
倒金字塔的 4 层结构：

第 1 层（前 1-2 句）：结论/核心信息
  写法：一句话说清楚"发生了什么 / 这是什么 / 需要你做什么"
  例子：「本周完成搜索性能优化，首页响应时间降低 73%。」
  ❌ 错误：「经过团队两周的努力，我们深入分析了搜索链路…」（这是背景，不是结论）

第 2 层（第 2-4 句）：关键影响
  写法：这件事影响了什么 / 影响了谁
  例子：「影响覆盖全站 120 万 DAU，移动端用户感知尤为明显。」
  ❌ 错误：「具体来说，我们做了以下几个方面的工作…」（跳过了影响直接讲细节）

第 3 层（第 1-2 段）：支持数据
  写法：用数字说话，不要用形容词
  例子：「P50 从 1.2s → 0.3s（↓75%），P99 从 8.4s → 2.1s（↓75%），错误率从 2.1% → 0.3%（↓86%）」
  ❌ 错误：「搜索体验有了极大改善，用户反馈非常好」（没有数字的"好"等于没说）

第 4 层（剩余段落）：背景细节
  写法：补充读者可能想知道的上下文
  例子：「本次优化主要手段：1) 索引重构 2) 缓存预加载 3) CDN 边缘节点部署」
  注意：很多读者不会读到这里——确保前 3 层已经传递了 80% 的价值
```

```markdown
- FAQ：简洁、准确、可被引用
- 事件报告：客观、无责备、聚焦改进

## File Organization（文件组织）
- SKILL.md：核心原则 + 路由逻辑（轻量）
- examples/：每种类型的详细模板和示例（按需加载）
```

## 6. 电商案例：大促期间运营日报自动生成

某美妆电商运营团队（天猫旗舰店，主营国货护肤品，团队 12 人）在 618 大促的 20 天活动期内，每天需要向品牌方（甲方）提交一份运营日报——含 GMV 达成率、各 SKU 销售排名、消耗推广费与 ROI、客服接待量、库存预警。

大促第一天，运营主管手工做日报花了 3 小时（导出 5 个后台数据源→拼接 Excel→写分析文字→排格式→发邮件），之后每天都花 2 小时以上，严重挤压了实时运营调整的时间。

**用 internal-comms 建立日报模板并自动生成**：

**Step 1：确定沟通类型**
→ 类型 4「状态报告」+ 类型 6「事件报告」（预警部分）的组合

**Step 2：建立日报模板（填空题替代作文题）**

```
## 📊 GMV 达成
- 昨日 GMV：______ 元（目标 ______ 元，达成率 ______%）
- 累计 GMV：______ 元（目标 ______ 元，达成率 ______%，距活动结束 ______ 天）
- 同比去年同日：______%（+/-______%）

## 🏆 TOP5 SKU
| 排名 | SKU | 销量 | GMV | 转化率 | 对比前日 |
|------|-----|------|-----|--------|---------|
| 1 | _____ | _____ | _____ | _____% | _____ |
| ... | ... | ... | ... | ... | ... |

## 📢 推广概览
- 昨日消耗：______ 元 | ROI：______ | 加购成本：______ 元/次
- 最优计划：______（ROI ______）
- 需关停计划：______（ROI < ______，已连续 ______ 天）

## 📦 库存预警 ⚠️
- 预警 SKU（库存 < 3 天销量）：______、______、______
- 已断货 SKU：______（建议替换为 ______）

## 🔧 今日重点
- □ ______
- □ ______
```

**Step 3：AI 自动填充 + 倒金字塔改写**

运营只需填入数据和今日重点的勾选项，AI 将数据改写为倒金字塔结构（结论在前）：

> 「昨日 GMV 达成 24.8 万，达成率 99.2%，距目标差 0.8 万。关键拉动力来自精华液品类（占 43% GMV，ROI 3.2）。库存预警：洁面慕斯仅剩 2 天销量，建议今日紧急补货。推广侧已关停 2 个 ROI < 1.2 的计划，预算重新分配至精华液品类。」

**效果**：
- 日报制作时间：从日均 2.5 小时降至 15 分钟（运营只填数据 + AI 改写）
- 大促 20 天累计节省运营主管约 47 小时——相当于多了 6 个完整工作日用于实时运营调整
- 品牌方（甲方）反馈：「今年的日报比去年清晰很多——一眼就看到 GMV 达成率和库存预警，去年翻到第三页才找到」

> 🔑 **启示**：大促期间的沟通效率不是「锦上添花」而是「生存问题」——运营主管每一分钟花在做日报上，就少了一分钟花在实时调价、加预算、盯库存上。填空题模板 + AI 倒金字塔改写的组合，把人从「写报告」的流程中解放出来，只做「提供关键数据」这件人最擅长的事。

- A) Price, Product, Promotion
- B) Progress, Plans, Problems
- C) People, Process, Platform

- B) 客观、无责备、聚焦改进措施——目的是防止再次发生，不是找人背锅

## 8. 答案

<details>
<summary>点击查看答案</summary>

**Q1**：**B** — Progress（本周完成了什么）、Plans（下周计划做什么）、Problems（遇到什么问题/阻塞需要帮助）。这是最常见的团队周报格式。

**Q2**：**B** — 事件报告的核心目的是"防止再次发生"，不是"追责"。使用客观、无责备的语气建立安全的复盘环境——如果团队害怕被追责，他们会隐藏问题而不是报告问题。

**Q3**：参考答案 — 优势：(1) SKILL.md 保持精简（只有原则和路由信息），不占用每次对话的上下文；(2) 新增沟通类型只需在 examples/ 中加一个文件，核心逻辑不变——可扩展；(3) 每种类型的详细规范按需加载，避免"加载了 FAQ 规范但用户只想写周报"的浪费。

**Q4**：参考答案 — "倒金字塔"结构：第一句说结果/核心信息，第二句说影响，第三段才开始给背景和细节。在企业沟通中有效的原因：高管可能只看前 3 行就决定"要不要继续读"——如果把核心信息埋在第 4 段，读者可能已经关掉了。"正金字塔"（先铺垫背景，最后说结论）适合叙事性写作，但在职场中后果是"你写了 5 分钟，读者读了 30 秒就关了"。

**Q5**：参考答案 — 3P 格式下读者建立了"扫描模式"——眼睛自动跳到 Progress 看完成了什么，扫 Problems 看有没有需要帮忙的，15 秒完成。换成散文式周报后，读者需要：通读全文找关键信息、自己脑补"这算 Progress 还是 Problems"、整个过程从 15 秒变成 5 分钟。读者的脑力花在了解析格式上，而不是理解内容上——这就是"认知摩擦"。

**Q6**：**C** — FAQ 回答应该"避免内部缩写过度"，因为 FAQ 的读者可能包括新员工、跨部门同事甚至外部客户。过度使用内部缩写会让非内部人员完全读不懂。

**Q7**：参考答案 — 给高管的领导层更新：概要 + 战略影响 + 数据趋势 + 决策请求。给团队的更新：细节 + 操作项 + 具体数据 + 个人任务。核心区别：高管需要"决策信息"，团队需要"执行指令"。

（5/7 通过）
</details>
