# L5-12：人机协作写作 —— 你和AI一起写文档，像两个作者合作

> 🎯 **学什么**：不是让 AI 替你写文档（写出来可能不准确），而是让 AI 像一位资深编辑一样——先采访你收集完整信息，然后逐节引导你写出高质量文档，最后用"盲测"验证读者是否能真正理解。三个阶段确保文档对真实读者有效。核心洞察：(1) 文档质量的乘法公式——任何一个因子为零，整体为零；(2) Stage 3 "盲测"是整个流程最天才的设计——用没有上下文的 Reader Claude 模拟真实读者，绕过"知识的诅咒"；(3) Stage 2 "策划筛选"是最容易被跳过的步骤——因为人有"面面俱到"的本能，但好的写作是"克制"的艺术。
> 💡 **难易度**：⭐⭐⭐⭐ | ⏱️ **预计时间**：45 分钟

***

## 1. 课程概览

> 💡 **白话小课堂**：想象你是一个作家，但你不擅长把想法组织成文章。你雇了一个"编辑教练"。他不是替你写——他先采访你，把你脑子里的东西全挖出来（Stage 1）；然后和你一起讨论每一节的结构，帮你筛选重点、打磨措辞（Stage 2）；最后找一群从来没看过文档的真实读者来读，看他们能不能理解（Stage 3）。doc-coauthoring 就是这个编辑教练——只不过它是一个 AI 工作流。

## 2. 文档质量的乘法公式

### 2.1 为什么是乘法不是加法

```
doc-coauthoring 的核心公式：

  文档质量 = 上下文质量 × 迭代次数 × 读者验证

为什么是乘法？
  → 乘法意味着"不可补偿性"
  → 任何一个因子为零 → 整体结果为零

三个因子的不可补偿性：

因子 1：上下文质量 = 0
  → 你什么都没告诉 AI，只说"帮我写个文档"
  → AI 基于通用知识生成了一份看起来很专业的文档
  → 但里面的公司背景、业务逻辑、技术约束全是猜的
  → 迭代 100 次、验证 100 遍也没用——地基就是歪的

因子 2：迭代次数 = 0
  → 你有很好的上下文，AI 生成的第一版也不错
  → 但你没有逐节打磨——直接从第一版发布了
  → 文档中不可避免地有逻辑断层、表达不清、结构混乱
  → 即使读者验证发现了问题，也已经发布了

因子 3：读者验证 = 0
  → 上下文充足 + 迭代充分 → 文档"看起来"很好
  → 但作者的大脑已经建立了完整的知识网络
  → 作者读自己的文档时会自动填补漏洞（知识的诅咒）
  → 真实读者没有这个知识网络 → "这文档讲的是啥？"
```

### 2.2 传统 AI 写作 vs doc-coauthoring

```
传统方式：
  用户给提示 → AI 生成文档 → 用户拿到文档
  问题链：
    (1) AI 缺少上下文 → 文档不准确
    (2) 没有迭代 → 结构粗糙
    (3) 没有盲测 → 只有作者自己看得懂

doc-coauthoring 方式：
  Stage 1 上下文收集 → Stage 2 逐节打磨 → Stage 3 读者盲测
  优势链：
    (1) 充分上下文 → 文档准确
    (2) 逐节打磨 → 结构清晰、表达精准
    (3) 盲测通过 → 真实读者能理解
```

## 3. Stage 1：上下文收集——投资回报率最高的 20 分钟

### 3.1 信息倾卸（Information Dump）

```
Stage 1 的核心环节：信息倾卸

什么是信息倾卸？
  → 用户不加组织地倾倒所有相关信息
  → 不需要结构化、不需要分类、不需要删减
  → 想到什么说什么——背景、目标、约束、担忧、已知方案、参考资料

为什么"不加组织"反而是正确做法？
  → 如果要求用户先整理好再说 → 用户会不自觉过滤信息
  → "我觉得这个不重要" → 但它可能就是关键上下文
  → 乱倒能捕捉到用户大脑中的所有关联——AI 可以后续帮忙整理

投入产出比：
  → 每多花 1 分钟收集上下文 → 后续至少节省 5 分钟返工
  → Stage 1 是整个流程中 ROI 最高的阶段
  → 但最多人想跳过它——"我就是想写个文档，为什么要先聊 20 分钟？"

实用技巧：
  → 打开手机录音，对着说 10 分钟 → 转文字丢给 AI
  → 比打字快 5 倍
  → 说出来的信息通常比写出来的更完整
```

### 3.2 退出条件：AI 能提出边缘情况

```
Stage 1 何时算"收集够了"？

退出条件：「当 AI 能提出边缘情况和权衡问题时」

什么算"边缘情况"级的问题？
  浅层问题（未达标）：
    → "你的目标受众是谁？"
    → "文档的目的是什么？"
    → 这些是基本信息——AI 还在扫盲阶段

  深层问题（达标）：
    → "如果用户用 5 年前的手机打开页面，加载时间超过 8 秒怎么办？"
    → "当退款率超过 15% 时，你们有没有自动熔断机制？"
    → "这个方案在数据量 100 倍时会发生什么？"
    → AI 已经理解了领域深度，开始主动思考边界

为什么这个退出条件有效？
  → AI 提出边缘情况 = AI 已经不只是"听懂了你说的"
  → AI 已经能模拟领域专家的思维方式
  → 此时 AI 补充的信息已经超过了你的原始输入
```

## 4. Stage 2：逐节细化——从 20 个点选出 3-5 个

### 4.1 四步逐节循环

```
Stage 2 不是"一次生成全文"，而是对每一节执行四步循环：

Step 1：脑暴（Brainstorm）
  → 针对本节内容，AI 列出所有可能覆盖的点
  → 不设限制——能想到多少列多少
  → 典型产出：15-25 个内容点

Step 2：策划筛选（Curate）⚠️ 最容易被跳过
  → 从 15-25 个点中选出 3-5 个最关键的
  → 筛选标准：删掉这个点后，本节核心信息还能传递吗？
  → 能 → 删掉 / 不能 → 保留
  → 这是"克制"的艺术

Step 3：起草（Draft）
  → 基于选出的 3-5 个点，撰写出本节初稿
  → 每个点讲深讲透，不蜻蜓点水
  → 段落之间用逻辑连接（不是"然后…然后…然后…"）

Step 4：打磨（Polish）
  → 检查：逻辑连贯吗？有歧义吗？可以更短吗？
  → 删除：无信息的填充词（"众所周知""显然""毫无疑问"）
  → 替换：抽象描述 → 具体例子 / 长句 → 短句 / 被动 → 主动

这四步的产出不是幻觉——每一步都有明确的输入和输出：
  输入：上一节的精炼稿 + 整体结构
  输出：本节精炼稿（经过筛选、起草、打磨）
```

### 4.2 策划筛选为什么最重要

```
人类有"面面俱到"的本能：
  → 脑暴阶段产生了 20 个内容点
  → "这 20 个点都挺好的，全放进去吧"
  → 每一节都在试图讲 20 个点
  → 结果：每个点都没讲深，读者只能记住混乱

"面面俱到"的代价：
  → 读者的注意力是有限资源
  → 一节 500 字讲 5 个点 = 每个点 100 字 → 够深
  → 一节 500 字讲 20 个点 = 每个点 25 字 → 什么都没讲清楚
  → 读者读完的体验："好像说了很多，但什么也没记住"

策划筛选的正确心态：
  → 你不是在"删掉好内容"——你在"保护读者的注意力"
  → 没选上的点不等于"没用"——只是不应该在这一节出现
  → 可以留到其他节、附录、或者另一篇文档
```

## 5. Stage 3：读者盲测——绕过知识的诅咒

### 5.1 为什么自己测不了自己的文档

```
"知识的诅咒"（Curse of Knowledge）：
  一旦你知道了某件事，你就无法想象不知道它是什么感觉。

这个心理学现象在文档写作中的表现：
  
  作者的体验：
    → 读完自己的文档 → "很清晰啊，我都能看懂"
    → 但作者的大脑在做"作弊"——自动填补文档中的漏洞
    → 作者看到的不是文档本身，而是"文档 + 大脑中的知识网络"
    → 那些缺失的上下文、模糊的表达、逻辑跳跃——
      作者的大脑自动补上了，作者甚至没意识到它们不存在

  真实读者的体验：
    → 读完这份文档 → "这段在说什么？"
    → "上文提到的 X 是什么？前面没定义过啊"
    → "结论是怎么跳到这的？中间的逻辑链断了"
    → 读者的大脑没有作者的"作弊工具"——他看到的就是白纸黑字

为什么自己测不了：
  → 不是说作者不够努力
  → 是作者在生理上无法模拟一个陌生读者的阅读体验
  → 就像知道魔术秘密的人，看魔术再也不会觉得神奇
```

### 5.2 Reader Claude 盲测机制

```
Stage 3 的设计：用"新鲜 Claude"做盲测

什么是"新鲜 Claude"？
  → 一个没有你上下文副本的 Claude 实例
  → 它只知道文档本身的内容
  → 它的知识 = 一个真实的陌生读者

测试流程：

Step 1：准备测试问题
  → 10 个问题，覆盖文档的 10 个核心信息点
  → 每个问题只有一个正确答案
  → 问题设计标准：如果读者真的理解了文档，应该能答对

Step 2：Reader Claude 回答
  → 给 Reader Claude 文档（没有其他上下文）
  → 让它回答 10 个问题
  → 它只能基于文档内容回答

Step 3：评分与分析
  → 10 个问题答对几个？
  → 答错的问题分两类：
    - 答案缺失：文档根本没提到这个信息 → 需要补充
    - 答案模糊：文档有提到但不清晰 → 需要重写

Step 4：修复与重测
  → 针对缺失/模糊的问题回到 Stage 2 修复
  → 修复后重新运行全部 10 个问题
  → 直到 Reader Claude 全部正确回答

退出条件：
  → Reader Claude 全部 10 题正确
  → 且不再出现新的盲点
  → 这才是"文档对真实读者有效"的信号
```

### 5.3 盲测修复流程

```
如果你的文档 Stage 3 测试得分是 6/10：

Step 1：分析每个错题
  Q3 答错 → 检查文档：发现"优惠券叠加规则"只在脚注里提了一句
  → 分类：答案模糊
  → 行动：把叠加规则提升到正文，用具体例子说明

  Q7 答错 → 检查文档：发现根本没提"退款时间窗口"
  → 分类：答案缺失
  → 行动：在相关章节补充退款时间窗口的说明

Step 2：回到 Stage 2 修复
  → 不是"在末尾加一段"
  → 是在正确的位置融入缺失/模糊的信息
  → 确保信息的出现顺序符合读者的认知流

Step 3：全部重测（非增量测试）
  → 修复后重新跑全部 10 题
  → 理由是：修改可能引入新的歧义
  → 增量只测改动的部分不能保证整体一致性

Step 4：实现 10/10
  → 这不只是"分数好看"
  → 这意味着一群"不知道你脑子里在想什么"的陌生人
    看完你的文档后，可以准确回答你关心的 10 个问题
  → 这才是"文档写好了"的真正定义
```

## 6. 结构拆解：文档协作 Skill 模板

```markdown
## 文档协作型 Skill 模板

### 核心特征
→ 管理对象 = 结构化文档的协作撰写流程
→ 核心原则 = 乘法公式 + 知识的诅咒 + 克制是写作的艺术
→ 关键设计 = 三阶段工作流 + 盲测验证 + 退出条件驱动

### 通用结构

## Quality Formula（质量公式）
文档质量 = 上下文质量 × 迭代次数 × 读者验证
→ 乘法：任何一个因子为 0，整体为 0

## Three-Stage Workflow（三阶段工作流）

Stage 1: Context Collection（上下文收集）
  - 信息倾卸：不加组织地倾倒所有相关信息
  - 退出条件：AI 能提出边缘情况和权衡问题
  - ROI：每多花 1 分钟收集 → 节省 5 分钟返工

Stage 2: Refinement & Structure（细化与结构）
  - 逐节四步循环：脑暴 → 策划筛选 → 起草 → 打磨
  - 策划筛选：从 20 个点选出 3-5 个（克制）
  - 退出条件：每一节都通过了打磨检查

Stage 3: Reader Testing（读者测试）
  - 用"新鲜 Claude"模拟真实读者（绕过知识的诅咒）
  - 10 题盲测 → 分析错题 → 修复 → 重测
  - 退出条件：Reader Claude 全部 10 题正确
```

## 7. 电商案例：品牌小红书种草笔记协作撰写

某国产护肤品品牌（主打敏感肌修护面霜，天猫月销 5000+）计划在小红书发起一轮种草投放——找 30 位 KOC（关键意见消费者）发布体验笔记。品牌方需要先撰写一份「种草笔记参考模板」发给 KOC，让她们「用自己的话改写」，确保品牌信息传递一致的同时保留达人的真实口吻。

用 doc-coauthoring 完成模板撰写。

**Stage 1：信息倾卸**

品牌主理人对着手机说了 10 分钟，转文字丢给 AI：

```
"我们的面霜主打'神经酰胺+积雪草'修护屏障，核心卖点是'28 天皮肤屏障修复率 31%'
——有第三方检测报告。目标用户是 25-35 岁有敏感肌困扰的女生，她们已经被
各种'猛药'成分（A 醇、刷酸）折腾坏了皮肤屏障。小红书笔记要避免像广告——
不能写'这款产品太好了快去买'，而要像'一个被敏感肌折磨多年的姐妹终于找到
解决方案'的分享。但又要真实——不能编造使用体验，不能 P 图过度。
价格是 168 元/50g，在天猫和抖音都有店……"
```

AI 提出的退出条件级问题：
- "如果 KOC 本身在使用 A 醇类产品，她的笔记能不能同时提 A 醇和你们的面霜？（交叉推广风险——品牌是否愿意和'猛药'成分并列？）"
- "笔记里能不能提到竞品名称？（比如'我用了 XX 品牌的面霜没效果才换了这个'——这在小红书很常见但法律风险很大）"
- "如果 30 位 KOC 中有 3 位写出来效果不好（肤质不匹配导致闷痘），品牌方的危机应对话术是什么？"

→ Stage 1 退出条件达成。

**Stage 2：逐节细化**

以「产品使用体验描述」这一节为例：

- 脑暴：列出 16 个可以写的内容点（质地/气味/吸收速度/使用前后对比/搭配建议……）
- 策划筛选：选出 5 个核心点——
  1. 第一印象（质地：冰淇淋乳霜，推开即化——不说「不油腻」这种小红书用烂的词）
  2. 使用第一周（泛红减少的具体感受——不要量化，要感受描述）
  3. 使用第四周（「上妆不卡粉了」——这是敏感肌用户最在意的日常改善信号）
  4. 搭配建议（精简护肤理念——只用洁面+面霜+防晒，呼应「修护屏障」）
  5. 价格感受（168 元/50g 用 2 个月，「一天不到 3 块钱」的换算）
- 起草 + 打磨：每一条提供 3 种不同口吻的参考文案（「精致生活型」「成分党型」「真实素人型」）

**Stage 3：盲测**

10 个测试问题覆盖合规性、品牌信息准确性、口吻真实性。Reader Claude 得分 7/10：

- 错题 1：「笔记模板是否明确禁止了 P 图过度的前后对比图？」——规则存在但藏在脚注，分类为「答案模糊」，修复：将违规行为提升为正文第一条
- 错题 2：「如果有用户评论问'A 醇能不能和这个面霜叠用'，KOC 的标准回复是什么？」——答案缺失，修复：补充 3 条常见 FAQ 的标准回复话术
- 错题 3：「模板中是否区分了'成分描述'和'功效宣称'的合规边界？」——答案缺失，修复：新增一条合规红线说明（功效用检测报告数据、成分只描述不宣称）

修复 → 重测 → 10/10 → 文档发给 30 位 KOC。

**效果**：
- 30 篇种草笔记的品牌信息一致性评分从 5.8/10（未用模板时的历史数据）提升到 9.1/10
- 合规风险：0 篇被小红书判定为违规广告（历史平均每次投放有 2-3 篇被限流）
- 笔记互动量（点赞+收藏+评论）中位数 1,240，比品牌历史投放中位数 720 提升 72%——归因于「真实口吻」模板让 KOC 写得更像真实分享而非念广告词

> 🔑 **启示**：种草笔记模板不是「限死文字」而是「给方向 + 给边界」。方向对了（Stage 2 策划筛选保留的 5 个核心点），KOC 用自己的话填充，内容自然好；边界清了（Stage 3 盲测暴露的合规盲区），30 个人写不会踩雷。好模板 = 明确的创造性空间。

## 8. 掌握检验

**Q1**：doc-coauthoring 的阶段顺序是什么？
- A) 读者测试 → 细化与结构 → 上下文收集
- B) 上下文收集 → 细化与结构 → 读者测试
- C) 细化与结构 → 上下文收集 → 读者测试
- D) 上下文收集 → 读者测试 → 细化与结构

**Q2**：文档质量公式"文档质量 = 上下文质量 x 迭代次数 x 读者验证"中，为什么使用乘法而非加法？
- A) 乘法计算更快
- B) 三个因子中任何一个为 0，整体结果就是 0——如果上下文质量是 0（什么都没告诉 AI），不管迭代 100 次、验证 100 遍，结果都是 0
- C) 加法公式已经被废弃
- D) 乘法可以让结果看起来更大

**Q3**：Stage 3 为什么必须用"去掉上下文的新鲜 Claude"做读者测试，而不能让作者自己测试？请用"知识的诅咒"（Curse of Knowledge）这个概念来解释。

**Q4**：Stage 2 逐节写作中，"策划筛选"（从 20 个内容点中选出 3-5 个）为什么是课程强调的最容易被跳过的步骤？跳过它会导致什么问题？

**Q5**：以下关于 Stage 1 "信息倾卸"（Information Dump）的描述，哪个是正确的？
- A) 它是一种浪费时间的步骤，应该跳过
- B) 用户应该先整理好结构再告诉 AI，不能"乱倒"
- C) 用户不加组织地倾倒所有相关信息——这是整个过程中投资回报率最高的步骤，每多花 1 分钟收集上下文，后续至少节省 5 分钟返工
- D) 信息倾卸只需要 5 分钟，超过就是低效

**Q6**：Stage 1 的"退出条件"是什么？为什么当 AI 能提出边缘情况和权衡问题时，说明上下文收集已经充分？

**Q7**：如果你的文档在 Stage 3 读者测试中，Reader Claude 在 10 个问题中只答对了 6 个——你应该怎么办？请描述你的修复流程。

## 9. 答案

<details>
<summary>点击查看答案</summary>

**Q1**：**B** — Stage 1: 上下文收集（弥合知识差）→ Stage 2: 细化与结构（逐节脑暴、策划、起草、打磨）→ Stage 3: 读者测试（用新鲜 Claude 验证可读性）。顺序不能颠倒——没有上下文就开始写（跳过 Stage 1）会导致文档不准确，没有测试就发布（跳过 Stage 3）会导致读者看不懂。

**Q2**：**B** — 乘法意味着不可补偿性。如果上下文质量是 0（用户什么都没告诉 AI，只说了"帮我写个文档"），那么迭代 100 次、验证 100 遍都没用——AI 在瞎编。如果上下文和迭代都很好，但没做读者验证（0），文档也可能是"只有作者自己看得懂"的自嗨。加法意味着一个因子低可以用另一个因子补偿，但在写作中这是错误的——一个没有上下文的文档不可能通过多次迭代变成好文档。

**Q3**：参考答案 — "知识的诅咒"是指：一旦你知道了某件事，你就无法想象不知道它是什么感觉。作者在写完文档后，大脑中已经建立了完整的知识网络，阅读自己的文档时大脑会自动"填补"文档中的漏洞——作者看不到缺失的上下文，因为他的大脑已经自动补上了。新鲜的 Claude 没有这个上下文——它看到的只是文档本身，能准确模拟一个"陌生的真实读者"的体验，发现所有"你以为读者知道但其实不知道"的盲区。

**Q4**：参考答案 — "策划筛选"被跳过是因为人类有"面面俱到"的本能——觉得"这 20 个点都挺好的，全放进去吧"。跳过它导致的问题是：当一节试图讲 20 个点时，每个点都没讲深讲透，读者只能记住混乱。好的写作是"克制"的艺术——从 20 个点中选出最关键的 3-5 个，把每一个讲深讲透。

**Q5**：**C** — 信息倾卸是 Stage 1 的核心环节，也是"整个过程中投资回报率最高的 20 分钟"。不加组织地倾倒能捕捉到用户大脑中的所有关联，后续 AI 可以帮你整理。如果要求用户先整理好再说，用户可能过滤掉了"我觉得不重要但其实关键"的信息。

**Q6**：参考答案 — 退出条件是"当 AI 能提出边缘情况和权衡问题时"——这表明 AI 已经理解了用户领域的足够深度，不再是浅层理解。例如：不是问"你的用户是谁"，而是问"如果用户用 5 年前的手机打开页面，加载时间超过 8 秒怎么办"。这种深度问题意味着 AI 已经从"了解基本信息"进入到"理解领域复杂性"阶段。

**Q7**：参考答案 — (1) 首先分析错在哪 4 个问题上——是答案缺失（文档根本没覆盖这个信息）还是答案模糊（文档有提到但不清晰）；(2) 对于答案缺失的问题 → 回到 Stage 2 在相关章节补充缺失的内容；(3) 对于答案模糊的问题 → 回到对应段落，用更具体的语言重写，去掉歧义；(4) 修复后重新运行全部 10 个问题的测试；(5) 直到 Reader Claude 全部正确回答且不再出现新的盲点，Stage 3 才退出。

（5/7 通过）
