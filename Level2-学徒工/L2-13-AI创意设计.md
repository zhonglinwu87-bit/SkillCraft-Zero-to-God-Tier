# L2-13：AI创意发散器 —— 抽象层的设计进化

> 🎯 **学什么**：从 `baoyu-image-gen`（L2-01）到 `baoyu-imagine`（本课）的设计演进——看一个 Skill 如何从「能用」（5 个后端用户自己选）进化到「好用」（自动选最优后端 + 统一参数 + Prompt（Prompt：给 AI 的输入指令） 存档）。核心洞察：好的抽象层让用户用「人的语言」描述需求（写实、动漫、扁平），差的抽象层让用户用「机器的语言」选配置（provider=stability, model=sd-xl）。
> 💡 **难易度**：⭐ | ⏱️ **预计时间**：40 分钟

***

## 1. 课程概览

> 💡 **白话小课堂**：你已经学了 L2-01 的「多后端抽象」——用户说一套参数，Skill 翻译给不同后端。但 `baoyu-image-gen` 还有个问题：用户仍然需要知道「用哪个后端」。本课的 `baoyu-imagine` 把这个选择也自动化了——用户说「我要一张日系动漫风格的角色」，Skill 自动判断「动漫风格 → Niji 最擅长 → 用 Niji」。旧版像餐厅给你 5 本菜单让你自己挑厨房，新版像你直接说「来份牛排」，服务员自动判断哪个厨房的牛排最好吃。

> **本课的独特定位**——抽象层进化：

| 特性 | baoyu-image-gen（旧） | baoyu-imagine（新/本课） |
|------|---------------------|------------------------|
| 后端选择 | **用户自己选** | **AI 自动选最优** |
| 参数接口 | 统一参数（但各后端有差异） | **完全统一，用户不需要知道后端** |
| 新增后端 | 改映射表 | **只加配置，不改代码** |
| Prompt 管理 | 无 | **自动存档到 prompts/ 目录** |
| 后端数量 | 5 个 | **10+ 个（DashScope、即梦、豆包等新增）** |

> 🔑 **核心秘诀**：抽象层的进化核心是「让用户用人的语言描述需求，而非机器的语言选配置」。产品经理思维：「我要一张日系动漫风格的海报」；后端工程师思维：「provider=niji, model=niji-v6, style=anime」。

> ⚠️ **避坑指南**：不记录 prompt 的后果——3 个月后你看到一张很好的图，但不记得用了什么 prompt 生成的，没法复现。就像炒了一道巨好吃的菜但没记菜谱，下次再也炒不出那个味。

## 2. 智能后端选择算法详解

### 2.1 从「用户选」到「AI 选」的设计变化

```
旧版（L2-01 baoyu-image-gen）：
  用户输入：「画一只猫，写实风格」
  AI 追问：「用哪个后端？DALL-E 3 / Stability AI / Imagen / Replicate？」
  用户困惑：「有什么区别？哪个更好？」
  → 用户需要懂后端差异 → 学习成本高

新版（L2-13 baoyu-imagine）：
  用户输入：「画一只猫，写实风格」
  AI 自动判断：
    关键词「写实」→ 擅长写实的后端：DALL-E 3 或 Stability AI
    DALL-E 3 写实物品质感更好 → 选 DALL-E 3
  AI 直接生成，不追问用户

  用户输入：「画一只猫，日系动漫风格」
  AI 自动判断：
    关键词「日系动漫」→ Niji（Midjourney 的动漫模型）最擅长
    → 选 Niji
```

### 2.2 风格→后端映射逻辑

```
风格关键词 → 最佳后端映射表：

photorealistic / 写实 / 照片级：
  → DALL-E 3（OpenAI）— 物体质感和光影最好
  → 备选：Stability AI SD-XL

anime / 动漫 / 二次元 / 日系：
  → Niji（Midjourney 动漫模型）— 动漫风格天花板
  → 备选：Animagine XL

illustration / 插画 / 扁平 / 矢量：
  → Replicate（Flux）— 插画风格多样性好
  → 备选：DALL-E 3

国潮 / 水墨 / 中国风：
  → 即梦（字节跳动）或 豆包 Seedream — 国风训练数据丰富
  → 备选：通义万象（阿里 DashScope）

3D / 渲染 / C4D：
  → Stability AI SD-XL — 3D 渲染风格模型多
  → 备选：DALL-E 3
```

### 2.3 为什么自动选择比让用户选择好？

```
让用户选择的问题：
  1. 用户不知道各后端的擅长领域（DALL-E 和 Imagen 在大多数场景下表现相近但各有偏重）
  2. 后端选择与 prompt 内容相关（同样的 prompt 在不同后端效果完全不同）
  3. 用户可能每次都选同一个（「我就用 DALL-E」），错过更适合的后端

自动选择的优势：
  1. 用户不需要学习后端差异
  2. 风格关键词 → 最擅长该风格的后端
  3. 用户关注创意，Skill 关注技术实现
```

## 3. Prompt 存档系统 —— 可迭代的创意资产

### 3.1 为什么 Prompt 必须存档？

```
场景 A（没有存档）：
  今天：「帮我生成一张咖啡店的海报」
  → 生成了，很好看
  3 个月后：「帮我生成一张类似的咖啡店海报」
  → 不记得之前用的什么 prompt → 从零开始 → 生成的风格完全不同
  → 品牌视觉不一致

场景 B（有存档）：
  今天：「帮我生成一张咖啡店的海报」
  → Skill 生成前先把 prompt 写入 prompts/01-coffee-shop-poster.md
  → Prompt 内容：Style: photorealistic, warm earth tones, 85mm lens...
  3 个月后：「帮我生成一张类似的咖啡店海报」
  → Skill 搜索 prompts/ 目录 → 找到 01-coffee-shop-poster.md
  → 基于之前的 prompt 微调 → 风格一致
```

### 3.2 Prompt 文件的约定结构

```
prompts/
├── 01-coffee-shop-poster.md     ← 咖啡店海报的 prompt
├── 02-product-mockup.md         ← 产品渲染图的 prompt
├── 03-social-post.md            ← 社交媒体帖子的 prompt
└── ...

文件命名：NN-描述性名称.md
文件内容：完整的 prompt + 元数据

示例 prompts/01-coffee-shop-poster.md：
---
date: 2026-05-10
backend: dall-e-3
style: photorealistic
result_rating: 8/10
---
Subject: 手冲咖啡器具，黄铜滤杯，蒸汽升腾
Style: photorealistic product photography
Composition: centered, warm overhead angle
Lighting: natural morning light, window side
```

### 3.3 Prompt 存档的三个价值

```
1. 可审计（Auditability）
   → 3 个月前那张图用了什么 prompt？
   → 打开 prompts/ 目录 → 直接看到
   → 和代码的 Git 历史一样——任何时候可追溯

2. 可迭代（Iterability）
   → 好 prompt → 存档 → 微调关键词 → 对比效果
   → 「把 warm earth tones 改成 cool blues → 看看效果差异」
   → 像 A/B 测试一样迭代你的 prompt

3. 可学习（Learnability）
   → 积累 50 个存档后 → 分析规律
   → 「为什么 photorealistic + 85mm lens 的组合出图率最高？」
   → 你的 prompt 能力不是靠记忆，是靠数据积累
```

> 🔑 **设计要点**：Prompt 存档和 L1-05 的「Prompt 落文件」是同一个理念——生成结果前先把 Prompt 保存为独立文件。批量化（500 张图）场景下尤其重要——500 个 Prompt 文件 = 500 次可追溯的创意决策。

## 4. 结构拆解：抽象进化型 Skill 模板

```markdown
## 抽象进化型 Skill 模板

### 核心特征
→ 在同一功能上，从「用户操控」进化到「AI 自动决策」
→ 核心变化 = 把用户需要做的选择自动化
→ 价值 = 降低使用门槛 × 提升输出质量

### 进化维度

1. 选择自动化
   旧：用户选后端
   新：AI 根据内容风格自动选最优后端

2. 参数统一化
   旧：不同后端不同参数
   新：完全统一，用户不需要知道后端存在

3. 结果可追溯
   旧：生成完就忘了
   新：Prompt 自动存档，可审计、可迭代、可学习

4. 扩展简单化
   旧：新增后端改映射代码
   新：新增后端只加配置
```

**什么时候需要抽象进化？** → 当现有 Skill 的「用户需要知道的技术细节」过多时——如果用户使用你的 Skill 前需要先学一套概念（provider / model / steps / aspectRatio），说明抽象层次还不够高。每一层进化都应该让用户少知道一个技术概念。

## 5. 电商案例：直播间背景布置创意方案

> 🛒 **实战案例**：某抖音珠宝直播间（主打翡翠挂件，客单价 ¥800-¥3,000），主播每天播 4 小时，直播间背景从开播至今半年没换过——一面灰墙 + 一个展示台 + 一盏环形灯。运营想升级直播间视觉但「不知道要什么风格」「不知道要花多少钱」「怕花钱搞完发现不适合珠宝品类」。
>
> **用 baoyu-imagine 的 AI 创意发散 + 多后端生成功能，产出 5 种风格 x 3 档预算 = 15 套直播间背景方案**：
>
> | 风格 | 低预算（¥500） | 中预算（¥2,000） | 高预算（¥8,000） | 适合什么品类 |
> |------|------|------|------|------|
> | **新中式** | 深色绒布+竹帘背景+单盏暖光射灯 | 定制「山水墨韵」喷绘背景布+仿古博古架+3 盏轨道灯 | 实木定制展柜+真丝帘幔+5 点布光系统 | 翡翠 / 文玩 / 茶叶 |
> | **轻奢极简** | 纯白背景纸+黑绒展示台 | 大理石纹理背景板+金属线条展架+偏光镜面底板 | 定制品牌发光 Logo 墙+悬浮展示台+调色温灯阵 | 珠宝 / 腕表 / 设计师首饰 |
> | **自然原木** | 原木纹贴纸+干花点缀 | 实木置物架+绿植墙（仿真）+暖黄串灯 | 定制实木场景（枯山水 + 苔藓 + 流水装置） | 食品 / 茶器 / 手工皮具 |
> | **科技未来** | 黑色植绒布+LED 灯带 | 亚克力发光展示台+动态 LED 背景屏（租赁） | 定制 3D 全息展柜+互动投影+沉浸式灯光编程 | 3C 数码 / 新奇特 |
> | **复古民国** | 旧报纸墙贴+老式台灯 | 民国风壁纸+复古留声机+蕾丝桌布 | 定制场景（老上海窗框+复古沙发+留声机真机） | 旗袍 / 古着 / 怀旧文创 |
>
> **落地执行**：运营选中「轻奢极简-中预算（¥2,000）」方案，baoyu-imagine 生成 8 张不同角度的参考效果图供装修师傅对照实施。3 天完成升级。
>
> **效果**（换背景后 30 天数据）：
> - 直播间平均停留时长：1 分 12 秒 → 2 分 47 秒
> - 互动率（评论/点赞）：1.8% → 4.3%
> - 场均 GMV：¥6,200 → ¥14,800（视觉升级 + 主播话术不变 = 纯粹视觉驱动增长）
> - 粉丝新增速度：日均 120 → 340
>
> > 🔑 **启示**：直播间的背景不是「装修」，是「无声的销售」。一面灰墙让 ¥3,000 的翡翠看起来像地摊货，一个对的展示台让 ¥800 的挂件看起来值 ¥3,000。AI 创意发散的核心价值不是「帮你设计」，而是「让你在动手花钱之前，先看到 15 种可能的模样」——决策效率从「脑子里想不出来」升级为「眼睛看到再选」。
## 6. 掌握检验

**Q1**：baoyu-imagine 相比 baoyu-image-gen 的核心改进不包括以下哪一项？
- A) 统一参数接口（用户不关心后端）
- B) 自动选择最优模型（用户不需要知道用哪个）
- C) 新增了视频生成功能
- D) 新后端只需加配置，不改代码

**Q2**：用户说「生成一张日系动漫风格的角色」。baoyu-imagine 的智能后端选择会怎么判断？
- A) 随机选一个后端
- B) AI 判断「动漫风格」→ 选择最擅长此风格的 Niji 或 Midjourney-style prompt
- C) 始终用 DALL-E 3 默认模型
- D) 弹出选择框让用户手动挑后端

**Q3**：Prompt 文件约定要求每次生成前必须把 prompt 写入 `prompts/NN-*.md`。这是为了满足哪三个目的？
- A) 省成本、省时间、省存储
- B) 可审计（知道生成了什么 prompt）、可迭代（基于之前的 prompt 调整）、可学习（分析哪些 prompt 效果好）
- C) 满足 API 调用规范、满足文件系统要求、满足隐私合规
- D) 方便分享给他人、方便备份到云端、方便用于 SEO

**Q4**：课程认为抽象层的设计进化核心是什么？
- A) 从「用户选后端」变成「AI 选后端」，让用户用「人的语言」描述需求而非「机器的语言」选配置
- B) 增加更多后端支持
- C) 优化 API 调用速度
- D) 统一所有后端为同一个 API 提供商

**Q5**：小汤建立了「国潮 prompt 库」，好用的 prompt 模板化后生成成功率从 50% 提升到 85%。请解释为什么 Prompt 存档系统能提升成功率？它和「写代码需要 Git 版本控制」有什么相似之处？

**Q6**：课程提到「用户说人话，AI 选后端」是产品经理思维，而「用户选 provider=stability, model=sd-xl」是后端工程师思维。请阐述这两种思维的本质区别，并举例说明为什么产品经理思维对用户更好。

## 7. 答案

<details>
<summary>点击查看答案</summary>

**Q1**：**C** — baoyu-imagine 的三大改进是统一参数接口、自动选择最优模型、新后端只加配置不改代码。它没有新增视频生成功能；它仍专注于图片生成，只是抽象层更高。

**Q2**：**B** — 智能后端选择根据用户描述的内容风格自动判断——写实 → DALL-E 3 或 Stability AI，动漫 → Niji 或 Midjourney-style prompt，国潮水墨 → 对应的擅长后端。用户不需要知道后端名字。

**Q3**：**B** — 可审计：你知道每张图用了什么 prompt 生成的（可追溯）；可迭代：看到好图可以基于之前 prompt 微调出变体（可优化）；可学习：分析哪些 prompt 结构和关键词效果好，哪些翻车（可积累）。

**Q4**：**A** — 好的抽象层让用户用「人的语言」（写实、动漫、扁平），差的抽象层让用户用「机器的语言」（provider=stability, model=sd-xl）。前者是产品经理思维，后者是后端工程师思维。

**Q5**：Prompt 存档提升成功率的原因：(1) 你不需要每次从零写 prompt——好用的 prompt 是经过验证的「菜谱」，直接复用或微调即可；(2) 坏用的 prompt 也存档了——知道什么不工作，避免重复犯错；(3) 随着积累，你的 prompt 库从「碰运气」变成「有据可查」。这和 Git 版本控制相似：代码不改一次就丢——git 让你回滚到之前能跑的版本，prompt 库让你回到之前出好图的 prompt。两者都是「可积累的知识资产」。

**Q6**：产品经理思维：以用户认知为中心——用户说「我要一张温暖文艺的咖啡店场景图」，AI 理解意图后自动选后端、调参数、生成结果。用户不需要知道技术细节。后端工程师思维：以技术实现为中心——用户需要知道 provider 名、model 名、参数格式、尺寸单位差异，然后才能用。产品经理思维更好因为：(1) 降低使用门槛——创意人员不需要学 API 文档；(2) 减少决策疲劳——用户不需要在 10 个后端之间纠结；(3) 让 AI 做它擅长的事——匹配和翻译，让人做擅长的事——创意和审美。

（5/6 通过）
