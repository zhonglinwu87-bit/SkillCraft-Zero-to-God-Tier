# L2-12：一键发布微博 —— 跨平台发布 Skill 的共同模式提取

> 🎯 **学什么**：对比 `baoyu-post-to-x`（L2-11）和 `baoyu-post-to-weibo`（本课），提取「平台发布 Skill 的共同骨架」——四个共同步骤 + 一张平台差异配置表。核心洞察：平台差异只有 10%，90% 的逻辑是重复的。不要为每个平台写独立 Skill——把差异抽成一行配置表，共性逻辑只写一次。
> 💡 **难易度**：⭐ | ⏱️ **预计时间**：35 分钟

***

## 1. 课程概览

> 💡 **白话小课堂**：你已经学了怎么发布到 X/Twitter（L2-11）——现在想想，如果要再做一个「发布到微博」「发布到 LinkedIn（LinkedIn：职场社交平台）」「发布到小红书」的 Skill，你要重写几遍？答案是：一遍都不用。所有「发布到某平台」的 Skill 都像快递发货——先确认你是本人（认证），再打包货物（适配平台格式），然后送出去（执行发布），最后查快递单号确认送到了（结果确认）。四个步骤，万变不离其宗。平台间的差异（280 字 vs 2000 字、`#hashtag` vs `#话题#`）存在一张配置表里，加新平台就加一行。

> **本课的独特定位**——跨平台抽象设计：

| 做法 | 每个平台一个独立 Skill | 共同骨架 + 平台配置表（本课） |
|------|---------------------|-------------------------|
| X/Twitter | baoyu-post-to-x（独立） | 共同骨架 + X 适配器配置 |
| 微博 | baoyu-post-to-weibo（独立） | 共同骨架 + 微博适配器配置 |
| LinkedIn | baoyu-post-to-linkedin（独立） | 共同骨架 + LinkedIn 适配器配置 |
| 维护成本 | 修改认证方式 → 每个 Skill 各改一遍 | **修改认证方式 → 改一次，所有平台生效** |

> 🔑 **核心秘诀**：平台差异表是跨平台 Skill 的灵魂。你只要维护这张表，加一个新平台（比如 LinkedIn）就只需要加一行配置，不需要重写整个 Skill。

> ⚠️ **避坑指南**：不要为每个平台写一个独立的 Skill！平台差异只有 10%，90% 的逻辑是重复的。如果你用独立 Skill 模式，修改一个 bug 需要同步 N 份代码——迟早会漏掉一个。

## 2. 共同骨架详解 —— 四个步骤的通用模式

### 2.1 四步骨架

```
所有「发布到某平台」的 Skill 共享同一个四步骨架：

Step 1: 认证（Authentication）
  → X: 浏览器 cookie（Chrome Profile）
  → 微博: 首次手动扫码登录，会话自动保存
  → LinkedIn: 浏览器 cookie
  → 共同逻辑：复用浏览器的登录状态（cookie（cookie：浏览器保存的登录凭证）），不管理独立的用户名/密码

Step 2: 内容适配（Content Adaptation）
  → X: 280 字符/条，Thread 拆分，#hashtag，4 张图
  → 微博: 2000 字符/条，#话题#，18 个文件
  → LinkedIn: 3000 字符，professional tone
  → 共同逻辑：根据平台配置表调整内容格式

Step 3: 执行发布（Execute Publish）
  → 所有平台：CDP 浏览器操作（打开 → 填写 → 点击发布）
  → 共同逻辑：模拟真人操作（随机延迟、正常鼠标轨迹）

Step 4: 结果确认（Verify Result）
  → 所有平台：截图确认 + 获取已发布内容的 URL
  → 共同逻辑：验证发布成功，提供可追溯的证明
```

### 2.2 平台差异配置表

90% 的逻辑复用，10% 的差异抽成一张配置表：

| 配置项 | X/Twitter | 微博 | LinkedIn |
|--------|----------|------|----------|
| 字符限制 | 280/条 | 2,000/条 | 3,000/条 |
| Thread/多段 | ✅ Thread | ❌ 单条长文 | ❌ 单条长文 |
| 媒体数量 | 最多 4 张 | 最多 18 个文件 | 最多 9 张 |
| 话题格式 | `#hashtag` | `#话题#` | `#hashtag` |
| @提及格式 | `@username` | `@昵称` | `@name` |
| 长文支持 | X 文章（需 Premium） | 头条文章（Markdown） | Article（需发布权限） |
| 语气 | 随意/对话体 | 随意/话题体 | professional tone |
| 认证方式 | Chrome cookie | 扫码 + 会话保存 | Chrome cookie |

### 2.3 微博的特殊之处

```
微博相比 X/Twitter 有几个独特的平台特性：

1. 扫码登录（首次）
   → X 可以复用 Chrome Profile 的登录态
   → 微博需要首次手动扫码 → 会话自动保存，后续无需再扫

2. 头条文章模式
   → 类似 X 文章（需要 Premium），但微博的头条文章对所有用户开放
   → Markdown 输入 → 自动转 HTML → 发布为头条文章
   → 包含封面图、标题、摘要的自动校验

3. 媒体数量上限高（18 个文件）
   → 适合图片密集型内容（如产品展示、旅行日记）
   → Skill 自动判断：超过 X 的 4 张限制 → 建议发布到微博
```

## 3. 跨平台发布策略 —— 一篇内容，多个版本

### 3.1 同源异形：一篇核心内容 → 多个平台版本

这是 L1-14「同源异形」原则在社交发布场景的直接应用：

```
核心内容：一篇关于「为什么春茶比秋茶贵 3 倍」的文章（2000 字）

→ X/Twitter 版本：6 条 Thread
  每条 200-280 字符，首条 Hook：「春茶和秋茶差了 3 倍价格——不是智商税，是科学」
  结构：Hook → 原因 1 → 原因 2 → 原因 3 → 数据对比 → CTA

→ 微博版本：2000 字长文
  保留原文完整结构，加话题 #春茶为什么贵# #茶叶科普#
  配 9 张图（茶园、采摘、加工过程）
  末尾加互动：「你喝春茶还是秋茶？评论区告诉我」

→ LinkedIn 版本：专业语气短文（1500 字符）
  侧重行业分析：「茶叶定价背后的农产品经济学」
  适合专业读者，引用数据来源
```

### 3.2 平台选择逻辑

```
用户说「发布到社交平台」→ Skill 不应该随机选一个

正确的选择逻辑：
  Q1: 内容长度？
    ├── ≤280 字符 → 所有平台都适合
    ├── 280-2000 字符 → 微博或 LinkedIn（X 需要拆分）
    └── >2000 字符 → 微博头条文章或拆分 Thread

  Q2: 媒体数量？
    ├── ≤4 张 → 所有平台
    ├── 5-9 张 → 微博/LinkedIn
    └── 10-18 张 → 微博

  Q3: 目标受众？
    ├── 中文受众 → 微博
    ├── 国际受众 → X/LinkedIn
    └── 专业受众 → LinkedIn
```

## 4. 结构拆解：跨平台发布 Skill 模板

```markdown
## 跨平台发布 Skill 模板

### 核心特征
→ 多个平台共享同一个四步骨架
→ 平台差异存在配置表中（10% 差异）
→ 共性逻辑只写一次（90% 复用）
→ 加新平台 = 加一行配置

### 通用结构

## Shared Skeleton（共同骨架）
Step 1: 认证 — 所有平台的认证方式
Step 2: 内容适配 — 根据平台配置表调整
Step 3: 执行发布 — CDP 浏览器操作
Step 4: 结果确认 — 截图/URL 验证

## Platform Adapters（平台配置表）
| 配置项 | 平台A | 平台B | 平台C |
| 字符限制 | N | N | N |
| 话题格式 | #tag | #tag# | #tag |
| ... | ... | ... | ... |

## Content Repurposing（内容复用）
→ 一篇核心内容 → 多个平台版本（L1-14 同源异形）
→ 平台限制决定内容形态（不是「改写」而是「适配」）

## Platform Selection Logic（平台选择）
→ 根据内容特征自动推荐最优平台
→ 字符长度、媒体数量、目标受众 三要素
```

## 5. 电商案例：淘宝店新品微博同步发布

> 🛒 **实战案例**：某淘宝女装店铺（粉丝 8.2 万）每周二/周五定时上新 5-8 款，每次都需要在微博同步发布新品图文。运营的手动流程：从淘宝后台复制标题和卖点，挑 4-9 张照片，从 5 个常用话题中挑 2-3 个，拼成一条微博——每款 15 分钟，8 款就是 2 小时。经常出现照片顺序错乱、话题标签忘了加、链接贴成旧款等问题。微博月均阅读量 3.5 万，单条互动（转评赞）平均 28。
>
> **用跨平台 Skill 做淘宝-微博一键同步发布**：
>
> | 平台差异 | 淘宝格式 | 微博适配 | Skill 处理方式 |
> |---------|---------|---------|-------------|
> | 标题 | 30 字卖点堆叠：「2026夏季新款法式碎花连衣裙收腰显瘦气质长裙」 | 40-60 字叙事型：「这次的碎花裙我们改了 3 版版型——收腰但不勒、V 领但不走光、长度刚好遮小腿肚。面料是 60 支高密棉，透气到能当防晒衫穿。#法式穿搭# #显瘦连衣裙#」 | 标题扩展+自动加话题标签 |
> | 图片 | 5 张主图（800x800） | 9 宫格（适配 1200x1200 推荐尺寸） | 自动选最佳 9 张 + resize |
> | 链接 | 淘宝链接 | 短链 + 淘口令 | 自动生成淘口令 |
> | 发布时间 | 手工决定 | 自动匹配黄金时段（工作日晚 8-10 点，周末早 10 点） | CDP 定时发布 |
>
> **效果**（微博同步策略执行 8 周后）：
> - 微博月均阅读量：3.5 万 → 18.2 万
> - 单条新品微博平均互动（转评赞）：28 → 186
> - 从微博引流到淘宝店铺的日均访客：120 → 680
> - 8 款新品发布总耗时：2 小时 → 20 分钟（含 5 分钟人工审核）
> - 发布零事故（连接错误、话题遗漏、图片错序等问题从每周 3-4 次降至 0 次）
>
> > 🔑 **启示**：淘宝店做微博不是「多发一个渠道」，而是「用微博的叙事方式重新讲一遍产品故事」。淘宝标题是给搜索引擎看的（堆关键词），微博内容是给人看的（讲故事+制造欲望）。跨平台 Skill 的核心不是复制粘贴，是把同一款产品的信息翻译成不同平台的语言。
## 6. 掌握检验

**Q1**：所有「发布到某平台」的 Skill 共同骨架 4 步是什么？
- A) 登录 → 排版 → 发布 → 分享
- B) 认证 → 内容适配 → 执行发布 → 结果确认
- C) 编码 → 压缩 → 上传 → 通知
- D) 抓取 → 分析 → 生成 → 发布

**Q2**：平台差异表在跨平台 Skill 设计中的核心作用是什么？
- A) 展示了每个平台的美学风格
- B) 将 10% 的平台差异存在一张表里，90% 的共用逻辑只需写一次——加新平台只加一行配置
- C) 帮助用户选择用哪个平台发布
- D) 记录每个平台的 API 密钥

**Q3**：根据平台差异表，微博和 X/Twitter 在话题格式上有什么不同？
- A) 微博用 `#话题#`，X 用 `#hashtag`
- B) 两者完全相同
- C) 微博不支持话题
- D) X 的话题需要加双井号

**Q4**：课程中提到「不要为每个平台写一个独立的 Skill」。这体现了什么设计原则？
- A) 每个平台各写一个 Skill 逻辑更清晰
- B) 平台差异只有 10%，90% 逻辑重复——提取共用部分，差异存配置表
- C) 所有平台统一成一个 Skill 后功能更强大
- D) 独立 Skill 更利于团队分工

**Q5**：小樱用 Skill 将「为什么春茶比秋茶贵 3 倍」一篇核心内容自动适配为微博、X、小红书三个版本。请分析：为什么微博版是 2000 字长文，而 X 版是 6 条 Thread？平台限制如何影响了内容形态？

**Q6**：如果你要在「统一发布 Skill」中新增一个平台适配器（如 LinkedIn），你需要在新平台的适配器配置里填哪些信息？新增这个平台对 Skill 的其他部分（如认证、内容适配、发布流程）需要做多少改动？

## 7. 答案

<details>

**Q1**：**B** — 四个步骤像快递发货：认证（确认你是谁，Cookie/Profile 管理）→ 内容适配（根据平台特性调整格式）→ 执行发布（CDP 浏览器操作）→ 结果确认（截图/URL 验证送达）。

**Q2**：**B** — 平台差异表是跨平台 Skill 的灵魂。没有表 = 3 个平台要写 3 个独立 Skill（维护噩梦）；有表 = 1 个 Skill + 1 张配置表，加新平台（LinkedIn）只需加一行。把 10% 差异抽出来，90% 共用逻辑复用。

**Q3**：**A** — 微博话题格式是 `#话题#`（前后都有井号），X/Twitter 是 `#hashtag`（只有前面有井号）。这些细微差异如果不通过配置表管理，很容易出错。

**Q4**：**B** — 如果不提取共用逻辑：(1) 修改认证方式需要在 3 个 Skill 各改一遍；(2) 修复 bug 需要同步 3 份代码；(3) 加新平台要复制粘贴整个 Skill 再修改。提取后加平台 = 加一行配置表。

**Q5**：微博支持 2000 字长文，可以保留原文的完整结构（4 个小标题+配图+文末抽奖），适合深度阅读。X 限制 280 字符/条，必须拆分——内容从「一篇完整文章」变成 6 条独立可读的推文串，每条像一个「知识碎片」：第 1 条钩子制造悬念，第 2-5 条逐条展开原因，第 6 条 CTA。平台限制重塑了内容形态——微博是「文章」，X 是「对话启动器」。

**Q6**：LinkedIn 适配器需要配置：字数限制（3000 字符）、支持的文件类型、话题格式（`#hashtag` 类似 X）、@提及格式（`@name`）、认证方式（Cookie）和语气要求（professional tone）。对 Skill 其他部分的改动极小——认证层（Step 1）复用 CDP 模式，执行发布层（Step 3）复用浏览器操作框架，内容适配层（Step 2）只需在配置表中加一行 LinkedIn 的规则。这就是平台差异表的核心价值：10% 的差异不影响 90% 的复用。
