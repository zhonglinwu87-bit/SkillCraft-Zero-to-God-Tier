# L2-08：免费工具获客策略 —— 决策型 Skill 的「先评估后行动」设计

> 🎯 **学什么**：如何设计一个「帮用户评估该不该做某事」的 Skill——不是教你怎么做工具，而是先帮你算清楚值不值得。核心洞察：一个好的决策型 Skill，最值钱的输出不是「怎么做」，而是「别做」——帮你避免一个 3 个月的大坑，比帮你省 2 小时值钱多了。
> 💡 **难易度**：⭐ | ⏱️ **预计时间**：35 分钟

***

## 1. 课程概览

> 💡 **白话小课堂**：这个 Skill 就像一个精打细算的投资顾问——你说「我想花 3 个月做个免费工具来吸引客户」，它不会马上教你写代码，而是先帮你算账：这个工具的目标关键词每月多少人搜索？用户用完后有多少会注册？开发要多久？竞品能不能轻松复制？最后给你一个分数——如果只有 15 分，它会说「别做，做一篇博客就够了」。如果能到 55 分，它会说「值得做，但先做个 MVP 用一个月验证一下」。

> **本课的独特定位**——决策型 Skill 的「先评估后行动」模式：

| 做法 | 执行型 Skill（「教你怎么做」） | 决策型 Skill（本课） |
|------|--------------------------|-------------------|
| 入口 | 「我要做 X，教我」 | **「我在考虑做 X，值得吗？」** |
| 输出 | 步骤教程 | **五维度评分 + 建议** |
| 最值钱的输出 | 怎么做 | **「别做」** |
| 关键设计 | 流程清晰 | **评估框架 + 评分区间 + 替代方案** |

> 🔑 **核心秘诀**：决策型 Skill 的特征——不问「你要做什么」，问「你的情况是什么」；不直接给答案，给评估框架；输出带评分而非二元结论；必须标注「不建议」的情况。

> ⚠️ **避坑指南**：做免费工具就像钓鱼——你要站在鱼的角度想「什么鱼饵对我最有吸引力」，而不是站在渔夫的角度想「我最擅长做什么鱼饵」。抠图工具 3 天就能做好，但它吸引的设计师不是你的 SaaS 工具的目标客户。

## 2. 五维度评估模型详解

### 2.1 为什么是 5 个维度？

每个维度对应免费工具失败的一种主要原因：

| 维度 | 衡量什么 | 如果忽略会导致什么 | 评分范围 |
|------|---------|-----------------|:--:|
| **SEO 潜力** | 目标关键词月搜索量 × 排名难度 | 工具做出来了但没人搜到 | 0-20 |
| **获客潜力** | 工具用户 → 注册/付费的转化预估 | 吸引了一堆人但没人买你的产品 | 0-20 |
| **开发成本** | 预估工时 + 长期维护成本 | 3 个月后发现维护比开发还累 | 0-20 |
| **竞争壁垒** | 竞品复制的难度和时间 | 上线 2 周竞品就抄走了 | 0-20 |
| **品牌价值** | 对品牌定位和认知的贡献 | 做了一堆工具但用户不知道你是干嘛的 | 0-20 |

**总分：0-100**，四个区间：
- **0-20**：不值得做——找替代方案（一篇博客、一份清单）
- **21-40**：谨慎做——先做 MVP（MVP：最小可行产品/版本），1 个月内用数据验证
- **41-60**：值得做——投入资源，但分阶段交付
- **61-80**：优先做——这是你的核心增长引擎

### 2.2 最容易被忽略的维度：获客潜力

获客潜力是五个维度里最重要的——也是最容易被忽略的：

```
什么是获客潜力？
  = 使用免费工具的用户中，有多少人会自然转化为你的付费用户？

高获客潜力示例：
  工具：SEO 健康度检测器
  产品：SEO 优化 SaaS（¥299/月）
  转化逻辑：用户检测出「你的网站 SEO 得分只有 32/100」
           → 看到建议「安装我们的插件可以自动修复 80% 的问题」
           → 自然转化
  获客潜力：9/10

低获客潜力示例：
  工具：在线抠图工具
  产品：电商详情页优化 SaaS（¥299/月）
  转化逻辑：设计师用抠图工具抠完图就走了
           → 不会想「要不要进一步优化我的淘宝详情页」
           → 断裂
  获客潜力：2/10
```

> 🔑 **核心洞察**：好做 ≠ 有效。抠图工具 3 天就能做好，但它吸引的人和你的目标客户不重叠。免费工具的核心原则：**工具解决的问题必须和产品解决的问题是同一个问题**——只是工具的版本更轻量。

### 2.3 开发成本不只是「写代码的时间」

```
真正的开发成本 = 首次开发 + 长期维护 + Bug 修复 + 用户支持

首次开发：预估 2 周
长期维护（每年）：浏览器兼容性更新、API 变化适配、服务器维护
Bug 修复：用户报告问题 → 排查 → 修 → 部署
用户支持：用户不知道怎么用 → 写文档 → 回复工单

一个看似「简单」的计算器工具：
  首次开发：2 周
  长期维护/年：约 50 小时（浏览器更新、依赖更新、用户问题）
  3 年总投入：2 周 + 150 小时维护 ≈ 约 2 个人月
```

## 3. 六种工具类型 —— 不是所有免费工具都是「工具」

### 3.1 类型全景

Skill 覆盖 6 种工具类型，每种有不同的适用场景和开发复杂度：

| 类型 | 示例 | 开发复杂度 | 最适合 | 获客潜力 |
|------|------|:--:|------|:--:|
| **计算器** | ROI（ROI：投资回报率） 计算器、价格计算器 | 中 | 帮用户量化价值 | 高 |
| **生成器** | 标题生成器、Logo 生成器 | 中-高 | 帮用户快速产出 | 高 |
| **分析器** | 网站体检、SEO 审计 | 高 | 帮用户发现问题 | 很高 |
| **评分器** | 产品成熟度评分 | 低-中 | 帮用户自我评估 | 中 |
| **清单工具** | 发布前检查清单 | 低 | 帮用户不遗漏 | 中 |
| **模板工具** | 合同模板、邮件模板 | 低 | 帮用户省时间 | 中 |

### 3.2 从痛点出发选择工具类型

```
流程：用户痛点 → 工具类型 → 评估可行性

用户痛点：「我不知道我的 SaaS 定价是否合理」
  → 分析器：「SaaS 定价健康度检测」（输入你的定价，分析合理性）
  → 获客潜力高：定价检测 → 定价优化工具 → 自然转化

用户痛点：「写广告文案总是没灵感」
  → 生成器：「广告标题 AI 生成器」（输入产品，生成 10 个标题）
  → 获客潜力高：标题生成 → AI 文案工具 → 自然转化
```

## 4. Build vs Buy vs 不做 —— 三个选项的决策树

### 4.1 决策树

```
在推荐「做一个免费工具」之前，先问三个问题：

Q1: 已有开源方案可以部署吗？
  ├── 是 → 部署开源方案（比自己写快 10 倍，成本接近零）
  │      → 示例：需要「网站状态监控工具」→ 已有多款开源方案可选
  └── 否 → 进入 Q2

Q2: 已有 SaaS 方案可以嵌入吗？
  ├── 是 → 谈判 white-label 或嵌入方案
  │      → 比自己开发快 5 倍，通常月费 $50-200
  └── 否 → 进入 Q3

Q3: 用户真的需要一个工具吗？还是只需要一篇指南？
  ├── 指南够用 → 不做了，写一篇深度博客（1 天 vs 3 个月）
  └── 指南不够 → 值得自己开发
```

### 4.2 「不做」为什么是最值钱的建议？

```
做一个不该做的免费工具的成本：
  - 3 个月的开发时间
  - 持续的维护负担（永远不是「做完就完了」）
  - 团队精力的分散（做工具就不能做产品迭代）
  - 机会成本（3 个月可以做 20 篇 SEO 文章或者跑 5 个增长实验）

Skill 说「别做，写一篇博客就够了」：
  - 帮用户省下了 3 个月
  - 帮用户避免了维护地狱
  - 帮用户把精力投入回报更高的事情

价值对比：
  「怎么做」→ 省了用户 2 小时的学习时间
  「别做」  → 省了用户 3 个月的机会成本
  「别做」的价值是「怎么做」的几百倍
```

## 5. 结构拆解：决策型 Skill 模板

从 L2-08 提取「决策型」Skill 的通用模板：

```markdown
## 决策型 Skill 模板

### 核心特征
→ 入口 = 「我在考虑做 X，值得吗？」（不是「教我做 X」）
→ 输出 = 多维度评分 + 建议区间 + 替代方案
→ 核心价值 = 「别做」比「怎么做」更有价值

### 通用结构

## Evaluation Framework（评估框架）
Dimension 1: [名称] — 衡量什么 — 如果忽略会怎样 — 评分范围
Dimension 2: [名称] — 衡量什么 — 如果忽略会怎样 — 评分范围
...
Dimension N: [名称] — 衡量什么 — 如果忽略会怎样 — 评分范围

## Scoring Ranges（评分区间）
0-20: 不建议 — 给出替代方案
21-40: 谨慎 — 先做 MVP 验证
41-60: 值得 — 分阶段投入
61-80: 优先 — 核心增长引擎

## Alternative Options（替代方案）
- Build（自建）：什么情况下选这个
- Buy（购买/部署开源）：什么情况下选这个
- Skip（不做）：什么情况下选这个
- Content（内容替代）：一篇指南可能就够了

## Decision Logic（决策树）
Q1 → Q2 → Q3 → 最终建议
```

**什么时候用决策型？** → 当用户带着「该不该做 X」的疑问而来时：免费工具评估、营销渠道选择、技术方案选型、定价策略决策——任何需要「先算账再行动」的场景。

## 6. 电商案例：电商工具SaaS免费标题打分器评估

> 🛒 **实战案例**：某电商工具 SaaS 团队（核心产品是「淘宝标题优化工具」，月费 ¥199）想做一款免费的「淘宝标题打分器」——输入商品链接，自动检测标题的搜索覆盖面、关键词密度、违禁词检测、可读性评分，输出一个总分和优化建议。目标是引流到付费工具。开发预估 2 周，1 个前端 + 1 个后端。
>
> **用决策型 Skill 做五维度评估**：
>
> | 维度 | 评分 | 分析 |
> |------|:--:|------|
> | SEO 潜力 | 16/20 | 「淘宝标题优化工具」月搜索量 3,600，「标题打分」「标题检测」长尾词合计 5,800/月——搜索需求明确 |
> | 获客潜力 | 18/20 | 用免费打分器的用户正在优化标题 → 当免费版只能给 60 分的标题打「不及格」但给不出具体改写方案 → 点击「用 AI 一键优化」跳转付费工具。获客路径极短，转化逻辑天然 |
> | 开发成本 | 14/20 | 调用淘宝开放平台 API 获取标题（免爬虫被封风险）+ NLP 分析。预估 2 周，维护成本低（算法迭代为主） |
> | 竞争壁垒 | 10/20 | 竞品可以抄功能——但打分模型背后是基于 50 万条淘宝标题训练的语料库，竞品短期追不上准确度 |
> | 品牌价值 | 15/20 | 强化「淘宝标题优化第一工具」的定位——免费的标题打分是建立「品类=品牌」认知的入口 |
>
> **总分：73/100 → 61-80 区间 → 优先做**
>
> **Skill 建议**：这是核心增长引擎级别的项目。建议先做标题打分（基础功能），上线后 2 周内追踪两个指标：A) 免费打分页到付费工具页的跳转率 > 8%；B) 跳转用户的付费转化率 > 3%。如果达标，立刻迭代到 2.0（加入竞品标题对比功能）。
>
> **实际上线后效果**：
> - 免费打分页上线 30 天，日均 UV 1,800（纯自然搜索）
> - 打分到付费工具的跳转率：11.3%（> 目标 8%）
> - 跳转用户的付费转化率：4.7%（> 目标 3%）
> - 30 天新增付费用户 76 人，其中 52 人（68%）的首次触点为免费打分器
> - 客户获取成本（CAC（CAC：客户获取成本））：几乎为 0（开发成本 ¥18,000 / 52 个新付费用户 = ¥346/人，远低于之前广告投放的 ¥820/人）

> 🔑 **启示**：免费工具不是「做一个就有效」——决定效果的 90% 是「做什么工具」而非「怎么做」。决策型 Skill 的价值在于：把 2 周的开发资源押在 73 分的项目上（标题打分器），而不是 32 分的项目上（比如做一个通用的「电商文案 AI 生成器」——获客路径太长，用户生成完就走）。

## 7. 掌握检验

**Q1**：决策型 Skill 的 4 个特征不包括以下哪一项？
- A) 不问「你要做什么」，问「你的情况是什么」
- B) 不直接给答案，给评估框架
- C) 输出带评分而非二元结论
- D) 总是推荐做工具，因为免费工具总是值得做

**Q2**：在五维度评估模型中，「获客潜力」衡量的是什么？
- A) 工具本身的技术先进程度
- B) 工具使用→注册/付费的转化率预估
- C) 工具的下载次数
- D) 工具在社交媒体上的分享数

**Q3**：小赵的「详情页体检工具」得分 39/50，落在哪个区间？意味着什么？
- A) 0-20 → 不值得做
- B) 21-40 → 谨慎做，建议先做 MVP 测试
- C) 41-60 → 值得做，全力投入
- D) 61-80 → 优先做，最高优先级

**Q4**：课程认为决策型 Skill 最值钱的输出是什么？
- A) 详细的实施步骤教程
- B) 竞品工具的对比分析
- C) 「别做」——帮你避免一个 3 个月的大坑
- D) 技术架构设计方案

**Q5**：小赵有三个工具想法：体检工具（获客潜力 9/10）、竞品分析器（获客潜力 7/10）、抠图工具（获客潜力 2/10）。为什么抠图工具好做（3 天）但获客潜力最低？这个例子揭示了什么核心原则？

**Q6**：课程中「Build vs Buy vs 不做」的决策框架，在推荐「做一个免费工具」之前要先检查哪三项？请用你自己的话解释，为什么「不做」的判断比「怎么做」更有价值？

## 8. 答案

<details>
<summary>点击查看答案</summary>

**Q1**：**D** — 决策型 Skill 的特征包括标注「不建议」的情况，防止浪费资源。它不会总是推荐做工具，而是先评估值不值得。其余 A/B/C 都是正确的特征描述。

**Q2**：**B** — 获客潜力衡量的是工具使用者中有多少人会转化为注册用户或付费用户。如果工具吸引的人群和你的目标用户不重叠（如抠图工具吸引设计师，但你的产品是电商详情页优化工具），获客潜力就低。

**Q3**：**B** — 21-40 分区间 = 谨慎做。Skill 建议先做一个最小版本（5 项核心检查而非 20 项），1 个月内上线测试，用数据验证假设再决定是否扩大。

**Q4**：**C** — 「别做」帮你避免一个 3 个月的大坑，比帮你省 2 小时值钱多了。好的决策型 Skill 最值钱的输出不是「怎么做」，而是「这个不该做」。

**Q5**：抠图工具的获客潜力低是因为「会用抠图工具的人不一定是你的客户」——一个设计师抠完图就走了，不会自然想「要不要进一步优化我的淘宝详情页」。核心原则：做免费工具就像钓鱼——要站在鱼的角度想「什么鱼饵对我最有吸引力」，而不是站在渔夫的角度想「我最擅长做什么鱼饵」。好做不等于有效。

**Q6**：三项检查：(1) 已有开源方案？→ 直接部署比自己写快 10 倍；(2) 已有 SaaS 可嵌入？→ 谈判 white-label 方案；(3) 用户真的需要工具吗？→ 可能一篇指南就够。「不做」更有价值是因为：做错一个免费工具的成本不是几天开发时间，而是 3 个月的机会成本 + 团队精力 + 维护负担。省下 3 个月去做了正确的事，比省 2 小时学会做一个不该做的工具，价值差了几十倍。

（5/6 通过）
