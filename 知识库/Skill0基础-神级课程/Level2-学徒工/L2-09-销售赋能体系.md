# L2-09：销售团队AI助手 —— 一对多输出型 Skill 设计

> 🎯 **学什么**：如何设计一个覆盖 7 种输出类型的 Skill——每种输出有独立的模板和场景匹配逻辑，像一个万能工具箱，销售要什么材料都能随时生成。核心洞察：不要让用户从 7 种类型中自己选——他们可能连自己需要什么都说不清楚。Skill（Skill：AI 技能模块） 应该根据场景关键词自动判断。
> 💡 **难易度**：⭐ | ⏱️ **预计时间**：35 分钟

***

## 1. 课程概览

> 💡 **白话小课堂**：这个 Skill 就像一个随时待命的销售军师团——销售说「下午要见一个做电商的客户」，Skill 自动判断「初次见面 → 给他准备一页纸简介 + 电商行业 ROI 计算器」；销售说「客户说我们太贵了」，Skill 自动判断「价格异议 → 给他准备异议处理文档 + 竞品价格拆解」。一把瑞士军刀上有剪刀、开瓶器、锯子、螺丝刀——销售面对客户时不同场景需要不同工具，Skill 就是这个瑞士军刀。

> **本课的独特定位**——一对多输出型 Skill：

| 做法 | 每种材料一个 Skill | 一对多输出型（本课） |
|------|-----------------|-------------------|
| 销售需要 PPT | 调用「PPT 生成 Skill」 | 同一个 Skill 自动判断并生成 |
| 销售需要一页纸 | 调用「一页纸生成 Skill」 | 同一个 Skill 自动判断并生成 |
| 销售需要异议处理 | 调用「异议处理 Skill」 | 同一个 Skill 自动判断并生成 |
| Skill 数量 | 7 个 | **1 个** |

> 🔑 **核心秘诀**：一对多输出的核心是两个设计：(1) 场景关键词 → 输出类型 的自动路由；(2) 每种输出类型有独立的模板——不能用一个「通用模板」应付所有场景（否则 ROI 计算器像 PPT，PPT 像产品说明书，四不像）。

> ⚠️ **避坑指南**：不要让每个销售都当「发明家」——一个销售发明了好的话术，应该变成全团队的标准装备。销售 Skill 就是把这种标准化做到极致：好方法写进 Skill，所有人共享，持续迭代。

## 2. 七种输出类型详解

### 2.1 类型全景

| # | 输出类型 | 一句话描述 | 自动触发词 |
|---|---------|-----------|-----------|
| 1 | **Sales Deck** | 10-12 页销售演示文稿 | 「开会」「演示」「pitch」 |
| 2 | **One-Pager** | 一页纸简介/会后留资 | 「见面」「留资料」「介绍」 |
| 3 | **Objection Handling** | 异议处理文档库 | 「太贵」「再看看」「竞品说」 |
| 4 | **Demo Script** | 演示脚本与话术 | 「演示」「demo」「介绍产品」 |
| 5 | **ROI Calculator** | 投资回报计算器 | 「值不值」「省多少」「回报」 |
| 6 | **Case Study Brief** | 案例研究简报（销售版） | 「案例」「有没有类似的」 |
| 7 | **Proposal Template** | 提案模板 | 「提案」「方案」「报价」 |

### 2.2 Sales Deck 的 7 页结构

```
Slide 1: Hook（钩子）——痛点提问或数据冲击
  → 前 30 秒决定客户是否继续听
  → 「你知道 87% 的电商客服每天花 3 小时回复重复问题吗？」

Slide 2: Problem（问题）——客户的现状和痛点
  → 让客户点头——「对，这就是我的问题」

Slide 3: Solution（方案）——你的产品如何解决这个问题
  → 不要讲功能，讲「你将会得到什么」

Slide 4: How It Works（怎么用）——产品使用流程
  → 越简单越好——「三步：安装、配置、自动运行」

Slide 5: Social Proof（社交证明）——客户案例/Logo 墙
  → 「XX、YY、ZZ 都在用，平均节省 40% 客服成本」

Slide 6: Pricing（定价）——价格与套餐
  → 放在 Slide 5 之后（先建立价值，再谈价格）

Slide 7: CTA + Next Steps（行动号召）
  → 「我们下周可以帮你接入试用，今天就给你开账号？」
```

### 2.3 异议处理文档库 —— 六类异议的回应框架

| 异议类型 | 客户说的 | 真正的意思 | 回应策略 |
|---------|---------|-----------|---------|
| **价格** | 「太贵了」 | 「我看不出值这么多」 | 算账：月费 ÷ 30 = 日费 vs 省下的成本 |
| **时机** | 「现在不是时候」 | 「我再拖拖，不急」 | 量化拖延成本：「晚一个月上线 = 多花 ¥X 客服工资」 |
| **竞品** | 「XX 比你们便宜」 | 「你们有什么不同？」 | 对比框架：不贬竞品，强调差异化 |
| **权限** | 「我需要请示老板」 | 「我无权决定，但不想直说」 | 提供决策材料：「这里有份一页纸方案可以直接给你老板看」 |
| **现状** | 「现在这样也挺好」 | 「不值得为改变付出成本」 | 放大痛点：「现在好 = 每月多花 ¥X 人工成本」 |
| **技术** | 「我们有安全顾虑」 | 「你的技术方案靠谱吗？」 | 提供技术白皮书 + 安全认证 |

**异议处理的核心公式**：

```
不是靠嘴硬，而是靠算账：

❌ 客户：「太贵了」
   销售：「我们的价格是行业标准」（嘴硬，无效）

✅ 客户：「太贵了」
   销售：「年费 9800 ÷ 12 = 817/月。你现在一个客服月薪 4000。
         这个工具能替代 1 个客服 = 每月净省 3183。
         也就是说你不仅不用花钱，每个月还多赚 3183。」（算账，有效）
```

### 2.4 其他输出类型速览

```
One-Pager（一页纸简介）：
  结构：一句话定位 + 三个核心功能 + 一个 ROI 数据 + CTA
  原则：能在电梯里讲完的东西才能写在一页纸上
  → 不是 PPT 的缩略版——是独立的信息产品

ROI Calculator（投资回报计算器）：
  三模块：输入（客户当前数据）→ 计算（你的产品带来的变化）→ 输出（省了多少/赚了多少）
  关键：输入要简单（3-5 个数字），输出要可视化（不是一堆数字，是「每年省 ¥38,196」）

Demo Script（演示脚本）：
  四种类型：发现通话、首次演示、技术深潜、高管概述
  每种类型有不同的时长、深度和关注点

Case Study Brief（案例简报）：
  销售格式 vs 营销格式：
  营销版：品牌故事、客户引言、漂亮的排版（用于官网）
  销售版：数据重点、决策原因、采购流程、关键联系人（用于销售说服）
```

## 3. 场景自动路由 —— 不让用户做选择

### 3.1 路由逻辑

```
用户输入 → 提取场景关键词 → 路由到输出类型

「下午见一个电商客户，帮我准备材料」
  → 关键词：「见」= 初次接触
  → 路由：One-Pager（一页纸简介）+ 电商行业 ROI Calculator

「客户说我们比 XX 贵一倍」
  → 关键词：「贵」= 价格异议
  → 路由：Objection Handling（价格异议模块）+ 竞品对比

「明天要给一个金融客户做产品演示」
  → 关键词：「演示」= 产品演示
  → 路由：Demo Script（首次演示脚本 + 金融行业案例）

「我们聊得不错，客户要方案」
  → 关键词：「方案」= 提案
  → 路由：Proposal Template（填入讨论过的要点）
```

### 3.2 路由失败了怎么办？

```
用户说的太模糊：「帮我准备销售材料」
  → 无法路由到单一类型
  → Skill 反问：「你要见什么类型的客户？处于哪个阶段？需要什么形式的材料？」
  → 不猜测，不随机——问清楚再生成
```

> 🔑 **设计要点**：路由失败时不猜测——这和 L1-10 的「先 Initial Assessment 再给建议」原则一致。不能确定输出类型时，宁可多问一句也不生成错误材料。

## 4. 结构拆解：一对多输出型 Skill 模板

从 L2-09 提取「一对多输出型」Skill 的通用模板：

```markdown
## 一对多输出型 Skill 模板

### 核心特征
→ 一个 Skill → N 种输出类型
→ 每种类型有独立的模板（不能用通用模板）
→ AI 根据场景关键词自动路由
→ 路由失败 → 反问用户而非猜测

### 通用结构

## Output Types（输出类型定义）
Type 1: [名称] — 一句话描述 — 触发关键词
Type 2: [名称] — 一句话描述 — 触发关键词
...
Type N: [名称] — 一句话描述 — 触发关键词

## Type-Specific Templates（独立模板）
每种类型的：
- 结构/页面框架
- 关键设计原则
- 好/坏示例
- 与其他类型的区别（防止混淆）

## Auto-Routing Logic（自动路由）
场景关键词 → 输出类型映射
路由失败 → 反问用户以澄清需求

## Shared Assets（共享资产）
- 产品信息库
- 客户行业数据
- 竞品对比数据
```

**什么时候用一对多输出型？** → 当同一个用户群体在不同场景下需要不同格式的材料时：销售团队（PPT/一页纸/异议处理/ROI 计算器/案例/提案/脚本）、市场团队（博客/社交媒体/邮件/白皮书/广告文案）、技术团队（API 文档/架构图/部署指南/FAQ）。

## 5. 电商案例：客服话术库批量生成应对三大场景

> 🛒 **实战案例**：某天猫母婴店（纸尿裤+婴儿湿巾，日均咨询 300+ 次）有 6 个客服轮班。客服主管最头疼三件事：客户砍价（「再便宜点我就下单了」）、差评威胁（「不满意我就给差评」）、退货纠纷（「拆开了但我就是不喜欢」）。每次遇到这类问题，客服要么不知道该怎么回要么回复太硬把客户惹毛。月度差评率 4.3%，退货纠纷率 8.1%。
>
> **用销售赋能 Skill 批量生成客服话术库**：
>
> | 场景类型 | 生成话术条数 | 典型话术示例 | 应用效果 |
> |---------|-----------|---------|
> | 砍价应对 | 15 条 | 「宝妈，这个价格已经是双十一同价了——而且今天下单额外送 3 包便携装湿巾（价值 ¥19.9），算下来比打折还划算。您要的话我现在就帮您备注赠品。」 | 客单流失率下降 30% |
> | 差评安抚 | 12 条 | 「非常抱歉给您不好的体验！您先别急——我这边直接帮您申请补发一包，到货后您用新的那包试试。如果还是不满意，我帮您全额退款，旧的不用退回来。」 | 差评率从 4.3% 降至 1.8% |
> | 退货挽留 | 10 条 | 「宝妈我理解，打开后觉得不合适很正常——要不这样，我帮您延期 15 天退货窗口，这期间您再用用看，不合适随时退。另外我把您的使用反馈记下来给产品部，他们会针对您提的问题改进。」 | 退货纠纷率从 8.1% 降至 4.6% |
> | 好评引导 | 8 条 | 「看您已经用了两周了，小宝贝用得习惯吗？如果满意的话方便给个带图评价吗？评价后截图发我，我给您申请一包同款湿巾作为答谢。」 | 好评率从 12% 升至 28% |
>
> **效果**：
> - 客服回复「不知道怎么回」的情况：从每天 15-20 次 → 每天 2-3 次（查话术库即可）
> - 新客服上手时间：2 周 → 4 天（话术库 = 标准答案，不需要背）
> - 客户满意度评分（平台 5 分制）：从 4.1 → 4.7
> - 月度差评率：4.3% → 1.8%（-58%）
> - 退货纠纷率：8.1% → 4.6%（-43%）

> 🔑 **启示**：客服话术的本质不是「会说话」，而是「在正确场景下说正确的话」。最好的话术永远不会藏在老客服的脑子里——它应该变成一个每个新客服打开就能查的标准化库。Skill 从「一次性生成」变成「持续积累」：每次有新的话术奏效，追加到库中，所有人同步享用。

## 6. 掌握检验

**Q1**：一对多输出 Skill 的核心设计要点是什么？
- A) 用一个通用模板生成所有类型的销售材料
- B) 先判断用户需要的材料类型，再用对应类型的独立模板生成
- C) 把所有 7 种材料合并成一个超大文档输出
- D) 让用户从 7 种类型中自己选，Skill 只负责生成

**Q2**：课程中提到 Sales Deck 模板包含 7 个 slide。以下哪个 slide 通常排第一？
- A) Pricing/Package（定价）
- B) Social Proof（客户案例/Logo 墙）
- C) Hook（痛点提问或数据冲击）
- D) CTA + Next Steps（行动号召）

**Q3**：为什么每种输出类型必须有独立模板，而不是通用模板？
- A) 通用模板代码量更少
- B) 每种材料有自己的「肌肉记忆」——ROI 计算器像数据报表、PPT 像演示故事、一页纸像电梯演讲，混用模板会导致「四不像」
- C) 通用模板渲染速度更快
- D) 独立模板让 SKILL.md 更长更好看

**Q4**：在电商案例中，盒火公司用 Skill 生成「异议处理文档」来应对「太贵了」的质疑。正确的回应逻辑是什么？
- A) 「我们的价格是行业标准」
- B) 「年费 9800 / 12 = 817/月，省一个客服工资 4000/月，净赚 3183/月」
- C) 「嫌贵可以买便宜的产品」
- D) 「贵有贵的道理」

**Q5**：盒火的新销售上手时间从 2 周缩到 3 天。Skill 在这个「销售培训加速」中扮演了什么角色？为什么标准化材料库比老销售口头传授更有效？

**Q6**：如果销售对 Skill 说「约了一个母婴店老板喝咖啡」，Skill 应该自动给出什么材料？为什么？如果销售说「客户说我们比 XX 贵一倍」，Skill 又该给什么？

## 7. 答案

<details>
<summary>点击查看答案</summary>

**Q1**：**B** — 核心设计是：先根据场景关键词判断类型（「要开会」→演示文稿，「太贵」→异议处理，「想看案例」→案例简报），再使用该类型的独立模板生成。不要让用户从 7 种材料中自己选——他们可能连自己需要什么都说不清楚。

**Q2**：**C** — Sales Deck 模板顺序是：Hook（痛点/数据冲击）→ Problem → Solution → How It Works → Social Proof → Pricing → CTA。Hook 放第一页因为前 30 秒决定了客户是否继续听下去。

**Q3**：**B** — 用通用模板会导致 ROI 计算器像 PPT、PPT 像产品说明书、产品说明书像邮件——「四不像」。演示文稿需要叙事逻辑（Hook→Problem→Solution），ROI 计算器需要数据框架（输入→计算→输出），一页纸需要极简电梯演讲（一句话+三个要点）。

**Q4**：**B** — 异议处理不是靠嘴硬，而是靠算账。与其说「我们不贵」，不如帮客户算：「你花 817 元/月，省 4000 元/月的客服工资，你每个月净赚 3183 元。」数据比雄辩更有说服力。

**Q5**：Skill 扮演了「标准化知识库」的角色——最好的话术、最有效的演示流程、最有说服力的 ROI 计算方式全部写进 Skill，所有销售共享。比老销售口头传授更有效是因为：(1) 不受老销售个人能力瓶颈限制；(2) 每次传授内容一致不丢失；(3) 好方法可以持续积累和优化；(4) 新销售可以反复查阅而非问一次就忘。

**Q6**：「约喝咖啡」是初次接触 → Skill 给 One-Pager（一页纸简介）+ 母婴行业定制版 ROI Calculator。One-Pager 轻量不压迫，ROI Calculator 让客户看到真金白银的价值。「比 XX 贵一倍」→ Objection Handling Doc，针对 XX 竞品逐条拆解「贵在哪」和「省在哪」，把价格异议转化为价值展示。

（5/6 通过）
