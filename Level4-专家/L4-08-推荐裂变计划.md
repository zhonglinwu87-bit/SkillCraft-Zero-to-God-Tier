# L4-08：推荐裂变引擎 —— 推荐循环四步 + 激励设计三维度 + 触发时机 + 联盟 vs 推荐

> 🎯 **学什么**：学会设计一个自运转的推荐机器——不是"请推荐我们"，而是设计一套触发→分享→转化→奖励的循环系统。区分客户推荐（信任驱动、量少但精）和联盟营销（佣金驱动、量大但质量不一），用触发时机（在Aha时刻弹窗而非注册时）和双边激励（让推荐者从"利用朋友赚钱"变成"给朋友送福利"）最大化推荐转化。核心洞察：被推荐者的落地体验是多数推荐项目失败的隐形杀手——你朋友发给你一个链接说"超好用"，你点进去看到一个通用首页，没有感到"被邀请"的独特性。
> 💡 **难易度**：⭐⭐ | ⏱️ **预计时间**：45 分钟

***

## 1. 课程概览

> 💡 **白话小课堂**：这个 Skill 就像一个**口碑传播引擎**——你有没有因为朋友推荐而去尝试一个产品？比如朋友说"这个记账App特别好用，而且通过我的链接注册，咱们两个都能免费升级"——你用了，觉得确实好用，然后又推荐给了你的同事。这就是推荐裂变——设计一套自运转的系统，让1个满意的用户为你带来10个新用户。

> **本课的独特定位**——增长引擎型 Skill：

| 特征 | L4-07（程序化SEO） | L4-08（本课） |
|------|-------------------|-------------|
| 增长方式 | 搜索引擎获取流量 | **用户口碑获取用户** |
| 核心资产 | 内容页面 | **用户关系和信任** |
| 可复制性 | 竞品可以模仿 | **信任难以复制** |

> 🔑 **核心秘诀**：触发时机是推荐的"命门"。在用户刚注册时就弹窗"邀请好友"——太早了，ta还没体验到价值，凭什么帮你推荐？正确时机是"首次Aha时刻"之后——用户刚收到好消息、刚完成一个重要任务、刚感受到产品价值的那一刻。

> ⚠️ **避坑指南**：激励不能"买用户"——如果推荐奖励太高（"推荐一个给¥50现金"），反而会吸引羊毛党——注册虚假账户骗奖励，但永远不会成为真正用户。激励应该与产品价值对齐：工具产品给功能解锁，内容产品给会员时长，社交产品给认可和地位。

> **来源**：Corey Haines marketingskills（`coreyhaines31/marketingskills --skill referral-program`）

## 2. 推荐 vs 联盟：两个不同的引擎

### 2.1 核心区别

```
Customer Referral（客户推荐）：
  推荐者：现有客户（已经使用了产品）
  动机：信任驱动——"我用过觉得好，推荐给你"
  体量：量少（一个客户最多推荐3-5人）但质量极高
  激励：一次性或有限奖励，通常非现金
  信任度：🔴🔴🔴 最高——来自使用过的人的真实推荐
  适合：有自然口碑的产品（产品本身好到用户愿意推荐）
  风险：过度激励会稀释信任（"他推荐我是为了拿奖励吧？"）

Affiliate Program（联盟营销）：
  推广者：可能不是客户（博主、KOL、评测网站）
  动机：佣金驱动——"我推荐这个工具，你买了我拿佣金"
  体量：量大（一个联盟者可能带来数百个用户）但质量不一
  激励：持续的佣金关系（按销售额/注册数分成）
  信任度：🟡 中等——取决于联盟者自身的信誉
  适合：需要触达你接触不到的受众
  风险：低质量联盟者可能损害品牌
```

### 2.2 选哪个？

```
决策问题：
  Q1: 你的产品是否有自然口碑？（用户会自发推荐吗？）
    → 是 → 先做客户推荐（成本低、质量高）
    → 否 → 先提升产品体验，再做推荐

  Q2: 你的目标受众在哪里？（你能直接触达吗？）
    → 能 → 客户推荐
    → 不能 → 联盟营销（触达你接触不到的圈子）

  Q3: 你的客单价和利润能支撑佣金吗？
    → 能（>¥500客单价，>50%毛利率）→ 联盟营销（持续佣金）
    → 不能 → 客户推荐（一次性/非现金激励）

混合策略（推荐）：
  → 先建立客户推荐计划（从现有满意客户中找种子）
  → 当客户推荐的自然增长稳定后，启动联盟计划
  → 两条腿走路：高信任度渠道（推荐）+ 高覆盖面渠道（联盟）
```

## 3. 推荐循环四步

### 3.1 完整循环

```
推荐循环 = 触发时刻 → 分享行为 → 转化被推荐者 → 发放奖励

Step 1: Trigger Moment（触发时刻）⚠️ 最关键
  → 什么时候让用户看到"推荐给朋友"的入口？
  
  ❌ 错误时机：
    - 注册后立即弹窗：用户还没体验到价值，凭什么帮你推荐？
    - 付费后立即弹窗：用户刚花了钱，现在让他拉人？感觉像"你在利用我"
  
  ✅ 正确时机：
    - 用户完成Aha时刻后：刚上传了第一张照片并看到AI生成的成果
    - 用户收到正面结果时："今日卡路里达标+体重下降"通知弹窗那刻
    - 用户达到里程碑时："你已经记账100天，总共省了¥5,000"
    - 用户表达满意后：NPS打分9-10分后
    - 太早=没体验价值不愿推荐，太晚=兴奋劲过了不会推荐

Step 2: Share Action（分享行为）
  → 让分享尽可能简单
  → 一键生成分享链接/图片/文案（不是让用户自己写）
  → 示例：自动生成一张精美图片"我坚持了XX天，减了XX公斤" + 邀请文案
  → 多渠道：微信/朋友圈/短信/邮件/复制链接

Step 3: Convert Referred（转化被推荐者）⚠️ 最容易被忽略
  → 被推荐者的落地体验是多数推荐项目失败的隐形杀手
  → 你朋友发给你一个链接说"超好用"，你点进去看到通用首页
  → 没有感到"被邀请"的独特性

  被推荐者落地页必须包含：
    - 推荐者的头像和名字（"XX推荐的好物"）
    - 推荐者的推荐语或精选内容
    - 专属的欢迎奖励（如首单8折）
    - 清晰的注册/购买按钮
    - 原因：被推荐者的信任起点完全不同——"朋友推荐我来"vs"我自己搜到的"

Step 4: Reward（发放奖励）
  → 即时发放（不要延迟——延迟会降低"推荐→再推荐"的动力）
  → 通知推荐者"你的朋友XX注册了，你获得了XX奖励"
  → 通知被推荐者"欢迎！XX送了你一个见面礼"
```

### 3.2 触发时机深度分析

```
用户生命周期中的推荐触点：

Day 0（注册）：❌ 太早
  → 用户还没体验价值
  → 弹窗推荐 = 骚扰

Day 1-3（激活期）：⚠️ 看情况
  → 如果Aha时刻在Day 1内发生 → 可以在Aha之后触发
  → 产品需要多天才能体现价值的 → 太早

Day 7-14（习惯养成期）：✅ 最佳窗口
  → 用户已经多次使用并感受到了持续价值
  → 自然的使用频率让推荐看起来不突兀

Day 30+（老用户）：✅ 持续推荐
  → 老用户是最佳推荐者（信任基础更深）
  → 但触发方式需要不同——不是弹窗，而是"你的朋友XX可能也需要这个"
  → 在用户取得新成就时触发（"你刚完成了第100次打卡！"）

每用户最多弹出推荐邀请的频率：
  → 不是"每次打开App都弹"
  → 合理的节奏：收到正面结果后→展示一次；如果用户关闭→7天冷却→新的正面结果后再次展示
```

## 4. 激励设计三维度

### 4.1 单边 vs 双边 vs 阶梯式

```
单边奖励（只奖励推荐者）：
  → 示例：推荐一人注册，推荐者得¥10优惠券
  → 问题：推荐者可能觉得"我在利用朋友赚钱"——尴尬
  → 适用于：推荐者是内容创作者（向粉丝推荐），而非朋友推荐

双边奖励（推荐者和被推荐者都受益）✅ 推荐
  → 示例：推荐一人注册并完成首单，双方各得15%折扣券
  → 优势：推荐者从"我在利用朋友赚钱"变成"我在给朋友送福利"
  → 被推荐者因为收到了专属优惠而更愿意尝试
  → 从心理上讲，把推荐行为从"索取"变成了"分享和给予"

阶梯式奖励（多级+持续激励）：
  → 示例：
    - 推荐1人 → 7天高级会员
    - 推荐3人 → 月度高级会员
    - 推荐10人 → 永久高级会员 + 入选"推荐名人堂"
  → 优势：持续激励，不会"推荐一次就停了"
  → 顶级推荐者需要不被金钱驱动的激励（认可、地位、独家访问）
```

### 4.2 激励类型与产品匹配

```
激励必须与产品价值对齐——不能"买用户"：

工具产品（SaaS/App）：
  → ✅ 功能解锁（高级功能N天、增加质保空间）
  → ✅ 会员时长（延长免费试用期）
  → ❌ ¥50现金——用户会因为¥50注册，但不会因为产品价值留下

内容产品（课程/会员）：
  → ✅ 会员时长（推荐一人=多一周会员）
  → ✅ 独家内容（只有推荐者能看的资料）
  → ❌ 现金——内容产品的用户在意的是知识/社区，不是钱

社交/社区产品：
  → ✅ 认可和地位（推荐排行榜、特殊徽章、名人堂）
  → ✅ 内部权限（提前体验新功能、内部数据报告）
  → ❌ 现金——社交产品的用户在意的是身份和归属，给钱反而俗

实物产品（电商）：
  → ✅ 双方折扣券（推荐有自然场景："这个好用，用我的码打折"）
  → ✅ 积分/赠品
  → ⚠️ 现金返现——谨慎使用，确认客单价能承受
```

## 5. 欺诈防范与指标追踪

### 5.1 防羊毛党规则

```
羊毛党特征：
  → 大量注册但从不使用产品
  → 同一设备/IP注册多个账号
  → 注册后立即推荐（没有正常使用行为）
  → 被推荐者也有类似的"僵尸"模式

防范规则：
  → 要求被推荐者完成有效行为（如完成首单、使用7天以上）才发奖励
  → 同一设备/IP的注册数量限制
  → 推荐者和被推荐者之间的使用行为关联检测
  → 手动审核异常高额推荐者
  → 关键：激励设计与产品价值对齐（如果奖励是延长会员时长，
    羊毛党拿了也没用——他们不在乎产品本身）
```

### 5.2 核心追踪指标

```
推荐计划健康指标：

活跃推荐者数（Active Referrers）：
  → 过去30天至少推荐1人的用户数
  → 这是推荐引擎的"马力"

推荐转化率（Referral Conversion Rate）：
  → 被推荐者中的注册率/付费率
  → 应该远高于其他渠道（因为信任基础）

推荐CAC（Referral CAC）：
  → 推荐奖励总成本 / 转化的被推荐者数
  → 理想情况下应该远低于广告CAC

被推荐客户LTV（Referred Customer LTV）：
  → 被推荐进来的客户，终身价值是否高于其他渠道？
  → 如果是——推荐是你最好的增长引擎
  → 如果否——推荐质量有问题（可能在"买用户"）

病毒系数（Viral Coefficient）：
  → 每个用户平均推荐了多少个新用户？
  → >1 → 病毒式增长（极罕见）
  → 0.5+ → 推荐对增长有显著贡献
  → <0.2 → 推荐不是你的主要增长引擎
```

## 6. 结构拆解：增长引擎型 Skill 模板

```markdown
## 增长引擎型 Skill 模板

### 核心特征
→ 增长方式 = 口碑驱动（用户拉用户）而非广告驱动
→ 关键设计 = 推荐循环四步 + 双边激励 + Aha时机触发
→ 核心区分 = 客户推荐（信任驱动）vs 联盟营销（佣金驱动）

### 通用结构

## Referral vs Affiliate（推荐 vs 联盟）
- 推荐者：现有客户 / 联盟者：可能不是客户
- 动机：信任（推荐）vs 佣金（联盟）
- 体量：量少质高 vs 量大质不一
- 决策：自然口碑？受众可触达？客单价够？

## Referral Loop（推荐循环四步）
Step 1: Trigger Moment（Aha时刻后，非注册时）
Step 2: Share Action（一键生成，多渠道）
Step 3: Convert Referred（落地页有推荐者信息+专属奖励）
Step 4: Reward（即时+双方通知）

## Incentive Design（激励设计）
- 单边 vs 双边（推荐）vs 阶梯式
- 激励与产品价值对齐（工具=功能、内容=时长、社交=认可、电商=折扣）
- 防羊毛党：需完成有效行为才发奖

## Metrics（核心指标）
- 活跃推荐者数 / 推荐转化率 / 推荐CAC / 被推荐客户LTV / 病毒系数
```

## 7. 电商案例：天猫母婴店铺"老带新"推荐有礼活动设计

> 🛒 **实战案例**：某天猫母婴辅食品牌（主营宝宝米饼+溶豆+小馒头，客单价¥69-¥189），月订单约15,000单，复购率35%。获客成本CAC ¥78，且广告渠道CPC从¥1.2涨到¥2.8两年翻了一倍多。但有一个天然优势——宝妈群体本身是高度社交化的，妈妈群里"你家宝宝吃什么辅食"是最常聊的话题之一。

**第一版推荐计划（失败）**：
- 规则：通过淘宝"分享有礼"工具，买家确认收货后弹窗"分享给好友，双方各得¥10优惠券"
- 数据：月推荐量仅380单（占月订单2.5%），推荐转化率4.2%
- 失败诊断：(1) 触发时机错误——确认收货时用户已完成购买闭环，没有分享动力；(2) 激励太弱——¥10券对¥69-¥189客单价没吸引力；(3) 没有分享素材——让宝妈自己写推荐语太麻烦

**改造方案——三步循环设计**：

| 要素 | 第一版 | 改造后 | 逻辑 |
|------|--------|--------|------|
| 触发时机 | 确认收货后弹窗 | "宝宝吃完了一整盒"时刻提醒——在App/小程序上展示"已食用X天"进度条，当宝宝吃完一整盒（约14-21天）后，自动弹出："宝宝已经吃了一整盒啦，分享宝宝的吃货日记给闺蜜，让她家宝宝也试试？" | Aha时刻 = 宝宝吃完了（产品被完全验证），而非收货（还没开始用） |
| 激励设计 | 单边：推荐者¥10券 | 双边阶梯式：推荐1人→推荐者得小馒头尝鲜装1盒+被推荐者首单减¥20；推荐3人→推荐者得¥89大礼包+被推荐者仍首单减¥20；推荐10人→推荐者全年新品免费试吃（价值约¥600） | 阶梯激励让推荐不止于1次；实物奖励比优惠券更有"妈妈社群炫耀价值" |
| 分享机制 | 通用链接，需手动打字 | 自动生成"宝宝吃货日记"精美卡片——宝宝月龄+喜欢的产品+妈妈的推荐语模板（可编辑），一键分享到微信 | 降低分享门槛：不是"发广告"，是"晒娃顺便推荐" |
| 落地页 | 通用店铺首页 | 专属落地页：显示推荐者昵称和宝宝名字+"XX妈妈推荐的宝宝同款"→首单减¥20→附推荐者家宝宝在吃这款产品的实拍图 | 被推荐者看到的不只是产品，而是"闺蜜家宝宝真的在吃" |
| 防羊毛党 | 无 | 被推荐者需完成首单且确认收货后（约14天），推荐者才获得奖励；同收货地址/同支付账户不计入有效推荐 | 羊毛党不会等14天确认收货 |

**推荐转化漏斗数据（改造后第3个月）**：

| 漏斗节点 | 数量 | 转化率 |
|---------|:---:|:-----:|
| 触发推荐弹窗（宝宝吃完一整盒） | 4,200人看到 | - |
| 点击"生成分享卡片" | 2,730人 | 65% |
| 实际分享出去（微信/朋友圈/妈妈群） | 2,050人 | 48.8%（占看到弹窗者） |
| 好友点击链接进入落地页 | 12,300人 | 每个分享者平均带来6个点击 |
| 好友下单（首单） | 1,845人 | 15%（落地页→下单转化率） |
| 好友确认收货（推荐者获得奖励） | 1,570人 | 85.1%（下单→确认收货率） |

**效果**：
- 月推荐订单量 380 → 1,570（+313%）
- 推荐CAC ¥78 → ¥19（比广告CAC ¥78低75.6%，且被推荐者质量更高）
- 被推荐者首单后60天复购率 38%（广告获客仅22%，因为推荐者的品牌信任传递给了被推荐者）
- 阶梯激励效果：推荐1人→2,050人完成；推荐3人→620人完成；推荐10人→88人完成（超级推荐者）

> 🔑 **启示**：母婴品类的推荐裂变成交不是"你推荐我买"，而是"你家宝宝在吃，我想给我家宝宝也试试"。触发时机必须从"运营视角的订单完成"切换到"用户视角的价值体验完成"——宝宝吃完一整盒=产品已被充分验证=妈妈有信心推荐。分享的不应该是"优惠券"，而是"我家宝宝的吃货日记"——前者是广告，后者是晒娃。

**Q1**：客户推荐（Customer Referral）和联盟营销（Affiliate Program）在推荐者动机、信任度和体量上的核心区别是什么？以下哪种更适合"有自然口碑的产品"？

- C) 两者没有区别
- D) 联盟营销——因为可以精确追踪佣金

**Q2**：推荐循环四步（Trigger Moment → Share Action → Convert Referred → Reward）中，哪一步最容易出问题？为什么"注册后立即弹窗邀请好友"是错误的触发时机？

- A) "推荐一个好友注册，直接给你打¥50现金"

- D) "每推荐一人注册即可提现¥200"

你运营一个让用户记录每日饮食并自动计算卡路里的App，用户最开心的时刻是"今天卡路里达标+体重下降"的通知。

## 9. 答案

<details>
<summary>点击查看答案</summary>

**Q1**：**B** — 客户推荐基于真实使用体验（信任度高、量相对低），适合有自然口碑的产品。联盟营销基于佣金驱动（量高但信任度要看联盟者信誉）。核心差异：推荐者动机——"我用了觉得好"vs"你付钱给我推广"。

**Q2**：参考答案 — 触发时机最容易出问题。注册后立即弹窗邀请好友是错的——用户还没体验到产品价值，凭什么帮你推荐？正确时机是"首次Aha时刻"之后——用户刚收到好消息、刚完成一个重要任务、刚感受到产品价值的那一刻。太早没体验价值、太晚兴奋劲过了。

**Q3**：**B** — "双方各得折扣券+需完成首单"将激励与产品价值对齐（不是现金套利），且要求被推荐者完成有效行为（首单）。A、C、D的高额现金奖励容易吸引羊毛党注册虚假账户骗奖励。

**Q4**：参考答案 — 应包含：(1) 推荐者的头像和名字（"XX推荐的好物"）；(2) 推荐者的推荐语或精选内容；(3) 专属的欢迎奖励（如首单8折）；(4) 清晰的注册/购买按钮。不能直接跳转通用首页，因为被推荐者没有感受到"被邀请"的独特性——"朋友推荐我来的"和"我自己搜到的"是完全不同的信任起点。

**Q5**：参考答案 — (1) 单边奖励——只有推荐者得益，推荐者觉得"我在利用朋友赚钱"；(2) 时机错误——注册后立即弹窗，用户还没体验到产品价值；(3) 激励类型不匹配——¥10优惠券对美妆用户没有吸引力，与产品价值不对齐。

**Q6**：参考答案 — 双边奖励让推荐者从"我在利用朋友赚钱"变成"我在给朋友送福利"——推荐者不会觉得尴尬，被推荐者也因为收到了专属优惠而更愿意尝试。从心理上讲，它把推荐行为从"索取"变成了"分享和给予"。

**Q7**：参考答案 —
- 触发时机：用户收到"今日卡路里达标+体重下降"通知后的那一刻弹窗——ta正处于"我做到了！"的兴奋峰值
- 激励设计：双边奖励——推荐者获得7天高级会员（解锁更多食谱），被推荐者获得首月8折
- 分享机制：不是分享"推荐链接"，而是分享"我的健康报告卡片"——自动生成一张精美图片（"坚持了XX天，减了XX公斤"）+ "跟我一起变健康"的邀请文案

**评分**：答对 5/7 = 通过。
