# L4-03：用户流失预警 —— 双轨防御 + 取消挽留五阶段 + 支付催款 + 健康度评分

> 🎯 **学什么**：学会区分主动流失（用户取消）和被动流失（支付失败）——两者需要完全不同的策略，但最终损失的都是钱。先搞定催款（被动流失，通常修复成本最低见效最快），再优化取消流程（主动流失），最后建立健康度评分预警系统（预防）。核心洞察：多数团队的流失防御优先级是反的——花大量精力去挽留想走的人，却对"想留但付不了款"的人视而不见。先把漏水的桶补上，再去接新水。
> 💡 **难易度**：⭐⭐⭐ | ⏱️ **预计时间**：50 分钟

***

## 1. 课程概览

> 💡 **白话小课堂**：这个 Skill 就像**健身房会员管理**——客人不来有两种情况：第一种是不想来了（太远了、太贵了、觉得没效果），这是"主动流失"——你需要打电话问原因、给个优惠让他回来试试。第二种是他想来但信用卡过期了、扣款失败——这是"被动流失"——他根本不知道没扣成，你只需要提醒他更新卡片就行。第二种比第一种容易修复100倍，但大多数健身房把90%的精力花在第一种上。

> **本课的独特定位**——双轨防御型 Skill：

| 特征 | L4-02（数据追踪） | L4-03（本课） |
|------|-----------------|-------------|
| 核心问题 | 怎么采集数据 | **怎么防止用户流失** |
| 关键区分 | 为决策追踪 | **主动流失 vs 被动流失——两套策略** |
| 优先级 | 数据基础 | **先被动→再主动→最后预警** |

> 🔑 **核心秘诀**：被动流失占30-50%，但通常比主动流失更容易修复。先搞定催款（被动）→ 再优化取消流程（主动）→ 最后建立预警系统（预防）。顺序反了就是花80%的精力去解决20%的问题。

> ⚠️ **避坑指南**：最常见的挽留失败——给所有取消的人统一发8折券。但对"用得不多"的用户，8折解决不了问题——他根本不用，免费给他也不会回来。挽留优惠必须匹配取消原因。

> **来源**：Corey Haines marketingskills（`coreyhaines31/marketingskills --skill churn-prevention`）

## 2. 流失的两种形态详解

### 2.1 主动 vs 被动

```
Voluntary Churn（主动流失）：用户主动选择取消
  占比：50-70%
  原因：
    → 产品太贵（"不值得这个价"）
    → 用得不多（"买了但基本不用"）
    → 缺功能（"我需要XX功能但你们没有"）
    → 竞品更好（"隔壁家了更好的工具"）
    → 体验问题（"太卡了/太难用了"）
  策略：取消挽留流程 + 退出调查 + 动态优惠 + 暂停/降级方案

Involuntary Churn（被动流失）：支付失败导致
  占比：30-50%
  原因：
    → 信用卡过期（最常见）
    → 余额不足（软拒付）
    → 银行风控拦截（软拒付）
    → 卡被盗/账户关闭（硬拒付）
  策略：智能重试 + 催款邮件序列 + 卡片更新工具
```

### 2.2 为什么优先级是"先被动、再主动、最后预警"

```
优先级逻辑链：

第一优先级：被动流失修复
  → 用户想留、想付钱、只是技术上卡住了
  → 你只需提醒他"你的卡过期了，点这里更新"
  → 修复成本极低、见效最快
  → 比喻：桶底有个洞，水在漏。先补洞。

第二优先级：主动流失挽留
  → 用户不想留了，你需要说服他
  → 需要理解原因 + 匹配合适的挽留方案
  → 成本中等、见效中等
  → 比喻：补好洞后再去劝离开的人回来

第三优先级：预警系统
  → 在用户还没决定离开之前就发现风险信号
  → 需要数据积累和模型调优
  → 成本最高但长期收益最大
  → 比喻：装水表监测异常用水，漏水前就修好
```

## 3. 取消挽留五阶段流程

### 3.1 五阶段总览

取消挽留就像"分手流程"——不能把人锁在家里不让走（那是违法的），但可以在他收拾行李的时候好好聊聊。先问"为什么想走"（Survey），然后根据原因给方案。

```
Phase 1: Cancel Intent（取消意图捕捉）
  → 用户在哪个页面/入口触发了取消？
  → 如果是深度埋藏的 → 提升曝光，让想取消的人找得到（防差评）
  → 如果是首页大按钮 → 可能需要适当增加查找难度（但不能阻止）

Phase 2: Exit Survey（退出调查）
  → 核心问题："是什么让你决定离开？"
  → 选项设计要覆盖主要流失原因：太贵/用得少/缺功能/竞品/体验
  → 允许自由文本（有些真实原因不在预设选项中）
  → 这是最宝贵的用户反馈——要走的人说的最真

Phase 3: Dynamic Save Offer（动态挽留方案）⚠️ 必须匹配取消原因
  → "太贵" → 提供3个月7折 + 降级方案选项
  → "用得不多" → 提供暂停订阅1-3个月 + 免费上手辅导
  → "缺功能" → 展示该功能已经在路线图中（如果是真的）+ 邀请加入内测
  → "竞品" → 展示你们独有的优势 + 竞品对比表
  → "体验问题" → 立即升级到技术支持

  ❌ 致命错误：给"缺功能"的用户发8折券
    → 价格不是他离开的原因，打折没用
    → 正确的挽留：展示该功能在路线图上 + 邀请他参与内测

Phase 4: Pause/Downgrade（暂停/降级选项）
  → 与其完全失去客户，不如让他先暂停
  → 暂停期间保留数据（降低回来的门槛）
  → 降级到免费/低价版（保留用户关系）

Phase 5: Final Confirm（最终确认）
  → "你确定要取消吗？你的XX数据将被保留XX天。"
  → 不阻止，只是确认——尊重用户的选择
  → 留下好印象：ta以后可能回来
```

### 3.2 "数据导出"= 死刑宣判信号

```
最高风险信号：用户开始导出数据

含义：
  → 他不是在"考虑"要不要走——他已经在为离开做准备了
  → 挽留时间窗口极短（可能只有几小时到一天）

正确响应（不是自动化邮件，是真人联系）：
  → 触发个人联系（电话或微信）
  → 问："我们看到你最近在导出数据。如果你遇到了什么问题，我可以直接帮你解决。"
  → 不要推销——先听，再对症下药

其他预警信号（从高到低）：
  → 数据导出启动（死刑宣判级）
  → 客服工单激增后突然停止（用户放弃了）
  → 登录频率连续下降（4周内减少50%+）
  → 功能使用深度下降（以前用10个功能，现在只用2个）
  → 邮件打开率下降
```

## 4. 支付催款系统

### 4.1 软拒付 vs 硬拒付

```
Soft Decline（软拒付）：
  → 原因：余额不足、银行风控临时拦截、处理器超时
  → 性质：临时性的——过几天可能就好了
  → 策略：
    - 7-10天内自动重试3-5次
    - 不同时间重试（避开银行维护窗口）
    - 恢复率通常 50-70%

Hard Decline（硬拒付）：
  → 原因：卡被盗、账户关闭、卡已注销
  → 性质：永久性的——这个人短期内不可能付钱
  → 策略：
    - 不重试（重试也是浪费）
    - 立即引导用户更换支付方式
    - 提供多种支付选项（支付宝、微信支付、其他卡）

软拒付像"朋友最近手头紧"——等等就有
硬拒付像"银行卡被冻结了"——让他换一张卡
```

### 4.2 催款邮件序列

```
标准时间节奏和语调变化：

Day 0（支付失败当天）：友好提醒
  → 主题：「你的付款未成功——点击这里更新」
  → 语调：轻松、有帮助——"可能是卡过期了，更新一下就好"
  → 行动：一键更新支付方式的链接

Day 3：帮助提醒
  → 主题：「快速提醒：请更新支付信息以保持访问」
  → 语调：仍然是帮助性的——"我们不想你失去访问权限"
  → 行动：同上 + "如有问题请回复此邮件"

Day 7：紧迫感
  → 主题：「3天后你的账户将被暂停」
  → 语调：紧迫但不威胁——"我们不想看到你离开"
  → 行动：更醒目的按钮 + 客服联系方式

Day 10：最终警告
  → 主题：「保持账户活跃的最后机会」
  → 语调：最后通牒但不失善意
  → 行动：最后更新机会 + "即使暂停，你的数据我们保留90天"

语调变化曲线：
  友好 → 帮助 → 紧迫 → 最后通牒
  不能一开始就威胁——用户还不知道发生了什么
```

## 5. 健康度评分与预警模型

### 5.1 健康度评分模型

```
Health Score = 加权多维综合评分（0-100）

维度与权重：

登录频率（0.30）：用户还在用你的产品吗？
  → 每天 → 10分 | 每周3-4次 → 7分 | 每周1次 → 4分 | 每月1次 → 1分

功能使用深度（0.25）：用户用了多少个核心功能？
  → 用了5+个核心功能 → 10分 | 3-4个 → 7分 | 1-2个 → 4分 | 只用1个 → 2分

使用趋势（0.20）：使用量在增加还是减少？
  → 连续增长 → 10分 | 稳定 → 7分 | 轻微下降 → 4分 | 急剧下降 → 1分

支持健康度（0.15）：客服互动质量
  → 近期有正面互动 → 10分 | 无互动 → 6分 | 多次投诉 → 2分

支付健康度（0.10）：付款历史
  → 从未失败 → 10分 | 偶尔失败但恢复 → 5分 | 近期多次失败 → 1分

分数分级与响应：
  → 70-100（健康）：常规培育，不要骚扰
  → 40-69（注意）：自动触发定向内容/教程
  → 0-39（严重）：触发个人联系干预（不是自动化邮件）
```

### 5.2 干预矩阵

```
风险等级 → 干预方式：

低风险（70-100）：
  → 什么都不做（过度干预反而骚扰）
  → 定期发送产品更新和技巧（保持联系但不Push）

中风险（40-69）：
  → 自动触发：教程、案例、新功能介绍
  → 匹配ta的使用模式——如果ta很少用某个功能，推送该功能的教程

高风险（0-39）：
  → 不：自动化邮件（不够）
  → 是：真人联系——电话、微信、个性化邮件
  → 询问："我们发现你最近用得少了，是不是遇到了什么问题？"
  → 注意：不是"求求你别走"，是"我想帮你解决问题"

死亡风险（数据导出/明确取消意图）：
  → 立即触发：真人电话联系
  → 时间窗口：几小时内
  → 不要推销，先诊断
```

## 6. 结构拆解：双轨防御型 Skill 模板

```markdown
## 双轨防御型 Skill 模板

### 核心特征
→ 核心区分 = 主动流失（用户不想留）vs 被动流失（用户想留但技术卡住）
→ 核心优先级 = 被动→主动→预防（按修复成本和见效速度排序）
→ 关键设计 = 取消挽留五阶段 + 催款邮件序列 + 健康度评分模型

### 通用结构

## Churn Types（流失类型）
Voluntary（主动）：占比50-70%，原因→策略
Involuntary（被动）：占比30-50%，原因→策略
优先级逻辑：被动修复最快→主动挽留→预警系统长期建设

## Cancellation Flow（取消挽留流程）
Phase 1-5: Cancel Intent → Exit Survey → Dynamic Save Offer
→ Pause/Downgrade → Final Confirm
核心：优惠必须匹配取消原因

## Dunning System（催款系统）
- 软拒付（Soft Decline）：7-10天内重试3-5次
- 硬拒付（Hard Decline）：不重试，引导换卡
- 邮件序列：Day 0/3/7/10 语调逐级升级

## Health Score（健康度评分）
加权公式：登录(0.30) + 功能(0.25) + 趋势(0.20) + 支持(0.15) + 支付(0.10)
风险分级 + 干预矩阵：低(不骚扰) / 中(自动内容) / 高(真人联系)
```

**什么时候用双轨防御型？** → 当你有订阅/会员/SaaS等周期性付费产品时——任何"用户需要持续付费才能保持使用"的场景。

## 7. 电商案例：天猫美妆店铺30天未复购用户召回策略

> 🛒 **实战案例**：某天猫美妆店铺，主营面部护肤品类（客单价¥129-¥459），月订单量约12,000单，但30天复购率仅8.7%（行业头部同类店铺15-20%）。团队只做了"新客首单优惠"，完全没有复购运营体系。核心痛点是——花¥85获客拉来的人，买一次就再也不回来了。

**流失分析（6个月订单数据）**：

| 用户分层 | 占比 | 6个月LTV | 复购率 | 流失特征 |
|---------|:----:|----------|:-----:|---------|
| 活跃用户（30天内有购买） | 18% | ¥687 | 64% | 定期回购，需维护 |
| 沉默用户（31-90天未购） | 37% | ¥312 | 21% | 用得好但忘了回来，或囤货还没用完 |
| 流失风险（91-180天未购） | 25% | ¥189 | 8% | 可能转向竞品，窗口即将关闭 |
| 已流失（>180天） | 20% | ¥98 | <2% | 几乎不可能自然回流 |

**RFM分层+定向优惠券召回方案**：

| RFM分层 | 定义 | 召回策略 | 优惠券设计 | 预期回流率 |
|---------|------|---------|-----------|:---------:|
| 高价值沉睡（R:31-90天, F≥3次, M≥¥400） | 买过多次、客单高但最近没来 | 专属客服微信1v1回访 + 新品试用装寄送 | ¥50无门槛券 + 双倍积分 | 35-40% |
| 中价值沉睡（R:31-90天, F=1-2次, M≥¥200） | 买了1-2次，体验过但未形成习惯 | 短信+淘宝消息："你上次买的精华快用完了吧？" | ¥20无门槛券 + 加赠小样 | 22-28% |
| 低价值沉睡（R:31-90天, F=1次, M<¥200） | 只买过一次低价品 | 关联推荐："用过洗面奶的客户，后来都买了同系列面霜" | 满¥150减¥30券 | 12-18% |
| 流失风险（R:91-180天） | 3-6个月没来，即将流失 | 大力度唤醒："我们上新品了，回来看看？" | ¥30无门槛券（限时72小时） | 8-12% |

**催款轨道（针对已下单未支付）**：
- 下单后30分钟未支付 → 自动淘宝消息："亲，订单保留30分钟，过期会释放库存哦"
- 下单后2小时未支付 → 短信："你的购物车里有1件商品，现在支付额外送面膜1片"
- 下单后24小时 → 最后提醒，不骚扰

**召回文案A/B测试（针对中价值沉睡用户）**：
- 文案A（功能型）："你上次购买的氨基酸洁面乳，现在复购立减¥20" → 点击率4.3%，转化率1.8%
- 文案B（时间关联型）："一瓶洁面乳正常用2个月，你上次买是67天前——该补货了。为你留了¥20券" → 点击率11.2%，转化率5.7%

**效果**（执行3个月后）：
- 30天复购率 8.7% → 15.3%（+75.9%）
- 召回总投入¥23,000（优惠券成本+客服人力），带来增量GMV ¥187,000，ROI 8.1:1
- 高价值沉睡用户回流率39%（60人中的23人）、中价值沉睡用户回流率25%（450人中的113人）

> 🔑 **启示**：复购召回的关键不是"发券"，而是"在对的时间用对的理由提醒对的人"。文案B比文案A转化率高3.2倍，区别只在于——文案B让用户觉得"你很懂我，知道我什么时候该买了"，文案A只是一个广告。

**Q7**：以下哪项是流失防御的正确优先级排序？
- A) 建立预警系统 → 优化取消流程 → 搞定催款
- B) 优化取消流程 → 建立预警系统 → 搞定催款
- C) 先搞定催款（被动流失）→ 再优化取消流程（主动流失）→ 最后建立预警系统（预防）
- D) 三者同时进行，不分先后

---

## 9. 答案

<details>
<summary>点击查看答案</summary>

**Q1**：参考答案 — 主动流失是用户主动选择取消（不想用了），占50-70%；被动流失是支付失败导致（想用但付不了款），占30-50%。很多团队的优先级是反的——花大量精力挽留想走的人（主动流失），却对"想留但付不了款"的人（被动流失）视而不见。被动流失通常比主动流失更容易修复，所以应该先堵被动、再挽主动、最后建预警。

**Q2**：**C** — 给"缺功能"的用户发8折券是匹配错误。缺功能的用户需要的是功能，不是打折——给他8折他也不会回来，因为价格不是他离开的原因。

**Q3**：**C** — 数据导出启动是最高风险信号。用户开始导出数据说明ta已经在为离开做准备，挽留时间窗口极短，应该触发个人联系（电话或微信），而非自动化邮件。

**Q4**：参考答案 — 软拒付（余额不足、处理器超时）是临时性的，7-10天内重试3-5次有50-70%的恢复率。硬拒付（卡被盗、账户关闭）是永久性的，不重试，必须引导用户更换新的支付方式。软拒付像"朋友最近手头紧"——等等就有；硬拒付像"银行卡被冻结"——这个人短期内不可能付钱。

**Q5**：参考答案 — Day 0 友好提醒（"支付未成功，更新卡片即可"）→ Day 3 帮助提醒（"快速提醒，请更新支付以保持访问"）→ Day 7 紧迫感（"3天后账户将暂停，请立即更新"）→ Day 10 最终警告（"保持账户活跃的最后机会"）。语调从友好→帮助→紧迫→最后通牒，逐级升级。

**Q6**：参考答案 — 登录频率（权重0.30）和功能使用（权重0.25）是两个最高权重。Health Score在0-39属于"严重"级别，应该触发个人联系干预（不是自动化邮件，是真人电话或微信）。

**Q7**：**C** — 正确优先级：先搞定被动流失（催款）→ 再搞定主动流失（取消流程）→ 最后建立预警系统（预防）。被动流失修复效果最快、成本最低。

**评分**：答对 5/7 = 通过。
